# Веб-клиент Daevox

React Router, React и Mantine предоставляют общий интерфейс локальных сервисов Daevox.

| Страница                        | Возможности                                                                                                         | Сервис                                             |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `/`                             | Стартовый экран; чаты Daevox пока не реализованы.                                                                   | —                                                  |
| `/telegram`                     | Подключение Telegram, выбор наблюдаемых чатов, история, саммари и автоответчик.                                     | [Основной backend](../backend/README.md)           |
| `/transcription`                | Файл или YouTube, запуск и отмена, прогресс и транскрипт с метками спикеров.                                        | [Сервис медиа](../transcription-backend/README.md) |
| `/voiceover` и `/voiceover/:id` | Библиотека видео, перевод, голоса, редактирование и повтор фраз, прогресс, ранний просмотр и скачивание результата. | [Сервис медиа](../transcription-backend/README.md) |

## Запуск

Из корня монорепозитория после `npm install`:

```sh
npm run dev --workspace @daevox/web-client
```

Vite слушает `127.0.0.1:5173` и не выбирает другой порт при занятости. Нужный backend
запускается в отдельном терминале по его README. Настройки Vite читаются из корневого `.env`:

| Переменная                   | По умолчанию            | Префикс запросов     |
| ---------------------------- | ----------------------- | -------------------- |
| `API_PROXY_TARGET`           | `http://127.0.0.1:3000` | `/api`               |
| `TRANSCRIPTION_PROXY_TARGET` | `http://127.0.0.1:3001` | `/trancription-api/` |

Браузер обращается к своему origin. Написание `/trancription-api/` соответствует действующему
контракту. Для production нужен reverse proxy с теми же маршрутами, поддержкой SSE и потоковой
выдачи медиа; Vite proxy действует только при разработке.

## Проверки и сборка

```sh
npm run verify --workspace @daevox/web-client
```

`verify` генерирует типы CSS Modules и маршрутов, проверяет типы, запускает unit-тесты с покрытием,
собирает приложение и Storybook. Браузерные e2e запускаются отдельно:

```sh
npm exec --workspace @daevox/web-client -- playwright install chromium
npm run test:e2e --workspace @daevox/web-client -- telegram.spec.ts auto-reply.spec.ts theme.spec.ts
npm run test:e2e:transcription --workspace @daevox/web-client
npm run test:e2e:voiceover --workspace @daevox/web-client
```

Явный список в первой команде тестов ограничивает общий Playwright-конфиг сценариями его
тестового backend. Для медиа нужны отдельные конфиги, окружение Python сервиса и FFmpeg;
они используют управляемые модельные процессы и не скачивают веса.

| Набор           | Порт тестового API | Порт веб-клиента |
| --------------- | ------------------ | ---------------- |
| Telegram и тема | `3001`             | `5174`           |
| Транскрибация   | `3002`             | `5175`           |
| Озвучка         | `3003`             | `5176`           |

Тесты запускают собственные серверы и не переиспользуют занятые порты.
В частности, Telegram e2e требует порт `3001`, который обычный сервис медиа использует по умолчанию.

Storybook компонентов:

```sh
npm run storybook --workspace @daevox/web-client
```

Список текущих и целевых возможностей: [обзор платформы](../../docs/platform.md).
