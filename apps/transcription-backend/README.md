# Локальная транскрибация, перевод и озвучка

FastAPI-сервис для вкладок `/transcription` и `/voiceover`. Транскрибация: файл или публичная запись YouTube →
FFmpeg → параллельные ASR (GigaAM-v3 для русского, Whisper large-v3 для английского)
и pyannote Community-1 → TXT/JSON.
Перевод видео: английская речь → локальная LLM → русская озвучка и видео с сохранением временной шкалы.
Один общий активный слот для транскрибации и озвучки, без очереди записей. Модели создаются в дочерних процессах
после команды пользователя; запуск API и health не загружают веса.
Подготовка TTS-моделей выполняется отдельно по инструкции выбранного движка.

## Запуск

Из корня monorepo:

```bash
npm run dev --workspace @daevox/transcription-backend
npm run dev --workspace @daevox/web-client
```

Нужны uv, Python 3.12 (uv установит его), FFmpeg/ffprobe с shared libraries,
Node.js для yt-dlp и доступные NVIDIA GPU. `dev` устанавливает GPU extra из `uv.lock`.
API слушает `127.0.0.1:3001`, Vite — `127.0.0.1:5173`.
Сервис запускается ровно с одним API worker. Несколько экземпляров сервиса
не обеспечивают общую блокировку операции; не направляйте proxy на несколько экземпляров.

Первичный доступ к Community-1:

1. Принять условия [модели](https://huggingface.co/pyannote/speaker-diarization-community-1).
2. После установки зависимостей выполнить `apps/transcription-backend/.venv/bin/hf auth login`.
   Альтернатива — серверная переменная окружения `HF_TOKEN`. Токен не передаётся в браузер.
3. Запустить транскрибацию из UI. Скачивание моделей происходит только здесь.

## Настройки окружения

| Переменная                           | По умолчанию                               | Назначение                                                  |
| ------------------------------------ | ------------------------------------------ | ----------------------------------------------------------- |
| `TRANSCRIPTION_HOST`                 | `127.0.0.1`                                | Адрес API                                                   |
| `TRANSCRIPTION_PORT`                 | `3001`                                     | Порт API                                                    |
| `TRANSCRIPTION_DATA_DIR`             | `data` относительно backend                | Результаты и временные файлы                                |
| `TRANSCRIPTION_ASR_GPU`              | `NVIDIA GeForce RTX 4070 Ti`               | Имя или UUID GPU; также допускается CUDA-номер с PCI_BUS_ID |
| `TRANSCRIPTION_DIARIZATION_GPU`      | `NVIDIA GeForce RTX 4070 Ti`               | Независимый выбор GPU                                       |
| `TRANSCRIPTION_ASR_REVISION`         | `edaa852ec7e145841d8ffdb056a99866b5f0a478` | Закреплённая revision large-v3                              |
| `TRANSCRIPTION_DIARIZATION_REVISION` | `3533c8cf8e369892e6b79ff1bf80f7b0286a54ee` | Закреплённая revision Community-1                           |
| `TRANSCRIPTION_UPLOAD_TIMEOUT`       | `60`                                       | Секунды ожидания начала upload, не лимит файла              |
| `TRANSCRIPTION_EVENT_HISTORY`        | `128`                                      | Число событий replay; дополнительно ограничен памятью 4 MiB |
| `TRANSCRIPTION_PROXY_TARGET`         | `http://127.0.0.1:3001`                    | Vite proxy; задаётся в корневом `.env` или окружении        |
| `HF_HUB_CACHE`                       | Стандартный кэш Hugging Face               | Постоянное хранение весов                                   |

Настройки Python передаются в окружении запуска, например
`TRANSCRIPTION_DATA_DIR=/path/to/transcriptions npm run dev --workspace @daevox/transcription-backend`.
Имена/UUID предпочтительнее номеров: порядок устройств CUDA и `nvidia-smi` может отличаться.
Никакого CPU fallback, уменьшения модели или INT8 нет. ASR и диаризация изолированы
в процессах. В режиме авто ASR-процесс сначала определяет язык через Whisper;
при русском освобождает Whisper и загружает GigaAM, иначе продолжает Whisper.
Выбор «Русский» пропускает загрузку Whisper и определение языка.

GigaAM использует веса [ai-sage/GigaAM-v3, e2e_rnnt](https://huggingface.co/ai-sage/GigaAM-v3/tree/e2e_rnnt),
закреплённые на `7655ad717f8122257385bb4b2f373db3697e8680` (настройка
`TRANSCRIPTION_GIGAAM_REVISION`). Официальная библиотека GigaAM закреплена в uv.lock
на `7447938d791c4f3e643386ee22c33777004293a5`; её декодер возвращает времена слов,
которых нет у HF-обёртки этой ревизии. Веса загружаются с `weights_only=True`,
архитектура проверяется строгой загрузкой state_dict; удалённый Python-код HF не выполняется.
Encoder работает в FP16 на ASR GPU, decoder — в FP32, как в официальном загрузчике.
Silero VAD из faster-whisper выделяет порции не длиннее 20 секунд; времена слов
сдвигаются к исходной записи, а соседние части одного спикера объединяются.
Времена RNN-T получены по кадрам выдачи токенов и не являются принудительным
выравниванием. Проверка качества текста и speaker-разметки требует эталона.

Результат хранится в `data/results/<безопасное-имя>-<uuid>/transcript.{txt,json}`.
JSON содержит слова, сгруппированные в последовательные реплики одного спикера, исходные интервалы спикеров,
фактические модели и признаки полноты. Отдельная alignment-модель не используется.
Границы порций ASR, паузы и изменение признака наложения не разрывают реплику:
новый блок начинается при смене спикера. Если в части реплики есть одновременная речь,
весь блок получает `overlap=true`; точные интервалы сохраняются в `speaker_turns`.
Текст без определённого спикера не объединяется между порциями ASR.
Отмена сохраняет принятый текст; ошибка диаризации сохраняет весь доступный ASR с
`status=failed`, `completeness.diarization=false`. Оригинальный файл не удаляется.
В UI доступна текущая/последняя операция до нового запуска или перезапуска API.

## Проверки

```bash
npm run verify --workspace @daevox/transcription-backend
npm run typecheck --workspace @daevox/web-client
npm test --workspace @daevox/web-client
npm run build --workspace @daevox/web-client
npm run test:e2e:transcription --workspace @daevox/web-client
```

Обычные проверки не требуют GPU и не скачивают модели. Backend-тесты подставляют
детерминированные внешние процессы на границе модельного runtime; HTTP, SSE,
файловая система и управление процессами настоящие. FFmpeg также проверяется
на сгенерированных источниках. Браузерные тесты поднимают настоящий FastAPI и Vite
на портах 3002/5175. Тестовый bootstrap не доступен из production-конфигурации.

Отчёт о выполненной приёмке: [acceptance.md](acceptance.md).
Функциональные тесты и CUDA smoke-test сами по себе не подтверждают качество моделей.

## Reverse proxy для собранного web-client

Vite proxy работает только в dev. Пример location для nginx (точное написание префикса):

```nginx
location /trancription-api/ {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_buffering off;
    proxy_request_buffering off;
    proxy_read_timeout 1d;
    proxy_send_timeout 1d;
    client_max_body_size 0;
}
```

Доступ предназначен для доверенного локального окружения. При внешней публикации
добавьте аутентификацию и TLS на proxy. Префикс `/api` продолжает обслуживать основной backend.

GPU-регрессионная проверка после установки extra: `RUN_GPU_TESTS=1 apps/transcription-backend/.venv/bin/pytest apps/transcription-backend/tests/test_gpu_runtime.py`. Она выполняет CUDA/cuDNN-операции на обеих GPU без скачивания моделей. Не устанавливайте одновременно пакеты `nvidia-cudnn-cu12` и `nvidia-cudnn-cu13`: их файлы конфликтуют.

Опциональная проверка уже скачанных моделей (без сети):

```bash
cd apps/transcription-backend
RUN_MODEL_TESTS=1 HF_HUB_OFFLINE=1 .venv/bin/pytest tests/test_gpu_runtime.py
```

Если кэш расположен нестандартно, укажите тот же `HF_HUB_CACHE`, с которым запускали UI.
Проверка выполняет полный HTTP pipeline на десяти минутах синтетической тишины;
её не следует считать оценкой WER/DER.

Реальная проверка GigaAM через HTTP на первых 45 секундах русской записи, отдельно
с `language=ru` и `language=auto` (при первом запуске скачает веса):

```bash
GIGAAM_TEST_AUDIO=/absolute/path/to/russian-recording.webm .venv/bin/pytest tests/test_gpu_runtime.py -k russian
```

## Перевод видео с озвучкой

Вкладка `/voiceover` принимает английское видео с аудио или публичную завершённую
YouTube-запись. После распознавания автоматически запускается единый этап «Озвучка»:
каждая фраза проходит перевод, синтез и подгонку. Этапы разных фраз перекрываются;
подгонка сохраняет исходный порядок, CosyVoice поддерживает два параллельных синтезатора.
Голоса назначаются по образцам спикеров; их можно изменить в настройках озвучки.
Затем готовятся видео и отдельная русская аудиодорожка. Библиотека сохраняется
в `data/voiceovers.sqlite3`, медиа — в `data/voiceovers/`. Активный слот общий
с транскрибацией. Отмена перевода удаляет его запись и файлы.

Без переопределений ASR, определение спикеров и TTS используют RTX 4070 Ti; ASR и
диаризация работают параллельно, TTS запускается после распознавания. Корневой `.env.example`
задаёт другую конфигурацию: ASR/диаризация на RTX 5080, TTS на RTX 4070 Ti и движок CosyVoice.
Выберите устройства своего компьютера; значения примера не являются defaults сервиса. Изменение настроек
требует перезапуска API; уже завершившуюся ошибкой запись нужно запустить заново.

Для перевода задайте `TRANSCRIPTION_LLM_BASE_URL` (по умолчанию
`http://127.0.0.1:8080/v1`) и `TRANSCRIPTION_LLM_MODEL` — идентификатор уже
загруженной модели локального сервера. Сервис не запускает и не меняет модель LLM.
Настройка TTS: `TRANSCRIPTION_TTS_GPU` (по умолчанию `NVIDIA GeForce RTX 4070 Ti`).

Движок выбирается через `TRANSCRIPTION_TTS_ENGINE`: `silero` (default в коде), `cosyvoice`
(в корневом `.env.example`), `chatterbox` или `qwen`. Для запуска достаточно подготовить выбранный движок.
CosyVoice, Chatterbox и Qwen используют отдельные Python-окружения; Silero — окружение backend.

### Silero

Для `TRANSCRIPTION_TTS_ENGINE=silero` модель должна быть установлена до обработки:

```bash
cd apps/transcription-backend
mkdir -p data/models
curl --fail --location https://models.silero.ai/models/tts/ru/v5_5_ru.pt --output data/models/v5_5_ru.pt
printf '%s\n' '50081637b602126ee06cb3bc8a744d25651d2da149ee8864b9a379bfdd934437  data/models/v5_5_ru.pt' | sha256sum --check
```

`TRANSCRIPTION_SILERO_PATH` и `TRANSCRIPTION_SILERO_SHA256` позволяют явно задать
путь и контрольную сумму. Загрузка артефакта разрешена только при совпадении SHA-256.
Пять образцов голосов кешируются отдельно от переводов.

Браузерная проверка: `npm run test:e2e:voiceover --workspace @daevox/web-client`.
Она использует модельные doubles, настоящий API, FFmpeg и браузер; проверка
качества реальных моделей проводится отдельно.

### CosyVoice 3 — 0.5B

Для CosyVoice используется `TRANSCRIPTION_TTS_ENGINE=cosyvoice` и отдельное
окружение Python 3.12. Из директории `apps/transcription-backend`:

```bash
git clone https://github.com/FunAudioLLM/CosyVoice.git data/tts-options/cosyvoice-source
git -C data/tts-options/cosyvoice-source checkout 074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc
git -C data/tts-options/cosyvoice-source submodule update --init --recursive
uv venv data/tts-options/cosyvoice-env --python 3.12
uv pip install --python data/tts-options/cosyvoice-env/bin/python -r requirements-cosyvoice.txt
.venv/bin/hf download FunAudioLLM/Fun-CosyVoice3-0.5B-2512 --revision 29e01c4e8d000f4bcd70751be16fa94bf3d85a18 --local-dir data/tts-options/cosyvoice3
```

Пути переопределяются через `TRANSCRIPTION_COSYVOICE_PYTHON`,
`TRANSCRIPTION_COSYVOICE_SOURCE_PATH`, `TRANSCRIPTION_COSYVOICE_MODEL_PATH`.
Worker использует обычные веса `llm.pt`, FP16 и выбранную `TRANSCRIPTION_TTS_GPU`;
ONNX-подготовка аудиообразца выполняется на CPU. TensorRT и vLLM не требуются.

Голос `demo` использует официальный `asset/cross_lingual_prompt.wav` из репозитория.
Это образец для первого сравнения, не специально подобранный русский диктор.
Свои голоса задаются JSON-объектом `TRANSCRIPTION_COSYVOICE_VOICES`, например
`{"narrator":"data/voices/narrator.wav"}`. Пути считаются от директории backend.
Запись должна быть не длиннее 30 секунд с частотой не ниже 16 кГц.
Применяется cross-lingual синтез без расшифровки образца; встроенная нормализация
английского/китайского отключена, чтобы не переписывать русский текст.
Все полученные аудиочасти объединяются в mono PCM WAV 24 кГц.
Проверки перевода остаются отключены: требуется только непустой результат.

### Chatterbox Multilingual V3

Chatterbox доступен через `TRANSCRIPTION_TTS_ENGINE=chatterbox`.
Chatterbox использует отдельное Python-окружение, чтобы не менять зависимости ASR.
Из директории `apps/transcription-backend`:

```bash
uv venv data/tts-options/chatterbox-env --python 3.12
uv pip install --python data/tts-options/chatterbox-env/bin/python -r requirements-chatterbox.txt --override chatterbox-overrides.txt
.venv/bin/hf download ResembleAI/chatterbox --revision 5bb1f6ee58e50c3b8d408bc82a6d3740c2db6e18 t3_mtl23ls_v3.safetensors ve.pt s3gen.pt grapheme_mtl_merged_expanded_v1.json conds.pt Cangjie5_TC.json --local-dir data/tts-options/chatterbox
npm run dev --workspace @daevox/transcription-backend
```

Worker загружает локальные веса V3 и синтезирует русский текст (`language_id=ru`).
`TRANSCRIPTION_CHATTERBOX_PYTHON` и `TRANSCRIPTION_CHATTERBOX_MODEL_PATH`
переопределяют пути. Без настройки образцов доступен один встроенный голос `default`.
Для своих голосов задайте `TRANSCRIPTION_CHATTERBOX_VOICES` как JSON-объект
`{"narrator":"data/voices/narrator.wav"}`. Пути считаются от директории backend;
для русского используйте чистую русскую запись. Каждый голос получает собственный
аудиообразец в интерфейсе. Интенсивность и CFG задаются через
`TRANSCRIPTION_CHATTERBOX_EXAGGERATION` и `TRANSCRIPTION_CHATTERBOX_CFG_WEIGHT`
(по умолчанию 0.5). Выход — mono PCM WAV 24 кГц со штатной меткой PerTh.

`TRANSCRIPTION_LLM_MODEL` должен совпадать с моделью работающего локального
сервера. GPU можно указать именем или UUID. API не запускает LLM.

### Qwen3-TTS 1.7B CustomVoice

Для `TRANSCRIPTION_TTS_ENGINE=qwen` используется отдельное окружение Python 3.12.
Из директории `apps/transcription-backend`:

`TRANSCRIPTION_QWEN_PYTHON` и `TRANSCRIPTION_QWEN_MODEL_PATH` переопределяют пути.
В интерфейсе доступны голоса `serena`, `aiden`, `uncle_fu`. Инструкции произнесения задаются

### Перевод, синтез и подгонка

При подгонке озвучки фраза получает окно до начала следующей фразы (последняя —
до конца видео). Пауза входит в окно; фактическое начало учитывает уже занятую
часть временной шкалы. Для перекрывающейся речи общее окно распределяется
пропорционально исходной длительности реплик, голоса размещаются последовательно.

После синтеза измеряется WAV. Минимальное необходимое ускорение вычисляется
как длительность WAV / доступное окно, в пределах **1×–1,5×**. После FFmpeg
длительность измеряется снова; небольшая погрешность корректируется ускорением
в пределах того же потолка. Если фраза не помещается, LLM получает измеренную
длительность и бюджет неускоренного синтеза (`окно × 1,5`), сокращает формулировку,
затем повторяется синтез. Всего максимум три попытки на фразу. Одинаковые тексты
используют кеш. Подгонка следующей фразы начинается после завершения этого цикла; её перевод и
первичный синтез могут быть уже готовы благодаря независимым очередям этапов.

Начальный перевод не получает временной бюджет. Полный перевод хранится отдельно
от адаптированного текста, проверяющей модели нет. Сохраняются история попыток,
измерения, выбранная скорость и полные WAV; ускорённый WAV не попадает в кеш
неускоренного синтеза. Неразрешённый конфликт получает `timing_overflow`, запись —
`incomplete`. Видео сохраняет скорость 1× и исходную длительность, слова не обрезаются.
Запросы к llama-server используют `enable_thinking=false`.

Конвейер сохраняет исходные слова и объединяет некоторые зависимые английские
обороты, которые ASR ошибочно разделил точкой. Это консервативные правила, а не
полный синтаксический анализ. Смена спикера и перекрытия не объединяются.
Перед переводом один LLM-запрос извлекает общий контекст ролика: тему, имена и
согласованные термины. Затем переводчик возвращает по одному основному тексту для
каждой реплики. Полный перевод хранится отдельно от адаптированного текста озвучки.
Единственное условие принятия перевода — наличие непустого текста для фразы.
Проверяющая модель не вызывается; проверки смысла, чисел, терминов и полноты
отключены. Если текста нет, выполняются ещё две попытки, затем фраза получает
`no_translation`. Словарь `TRANSCRIPTION_TTS_GLOSSARY` используется только
в инструкции переводчику, без проверки результата.

Основной вариант синтезируется один раз и измеряется по WAV. Перед размещением
сокращается середина тихих пауз длиной от 400 мс: сохраняются по 120 мс с обеих
сторон. При переполнении адаптация и синтез повторяются только для проблемной
реплики. Контентный кэш сохраняет остальные фрагменты для локального повтора.

Озвучка использует независимые очереди перевода и первичного синтеза без
ограничения числа фраз в работе. Каждый этап сразу берёт следующую доступную
фразу после завершения предыдущей, независимо от продвижения подгонки. LLM и TTS
используют независимые очереди. Для CosyVoice одновременно работают два
синтезатора на выбранной GPU; остальные движки выполняют один синтез.
`TRANSCRIPTION_COSYVOICE_WORKERS=1` возвращает режим одного синтезатора,
значение по умолчанию — `2`. Каждый процесс держит собственную модель.
Результаты синтеза ожидают подгонки на диске; в памяти очереди хранят метаданные.
Каждый процесс CosyVoice загружает модель один раз на озвучку записи и
использует её для фраз и повторных попыток из общей очереди. После завершения или отмены процесс освобождает GPU.
Подгонка и размещение выполняются в исходном порядке, с учётом фактического конца
предыдущей фразы. Готовность по-прежнему означает завершённую подгонку.

Сборка использует только фразы, уложившиеся в исходную временную шкалу. Прежний
`TRANSCRIPTION_VOICEOVER_MAX_LAG` больше не разрешает дополнительное отставание:
конфликт определяется по доступному окну. Все синтезированные фразы доступны для
прослушивания, включая проблемные. В списке фраз можно раскрыть историю попыток,
изменить текст озвучки и повторить только эту реплику. Остальные используют кеш.
Старые записи открываются без миграции; подробные измерения появляются при
следующей озвучке.

### Разделение речи и фона

Фон выделяет Demucs 4.0.1 с моделью `htdemucs`. Используется официальный checkpoint
`955717e8-8726e21a.th`; перед загрузкой worker проверяет SHA-256
`8726e21a993978c7ba086d3872e7608d7d5bfca646ca4aca459ffda844faa8b4`.
Установите файл в torch cache; до обработки worker требует его наличия и суммы:

```bash
mkdir -p ~/.cache/torch/hub/checkpoints
curl --fail --location https://dl.fbaipublicfiles.com/demucs/hybrid_transformer/955717e8-8726e21a.th --output ~/.cache/torch/hub/checkpoints/955717e8-8726e21a.th
echo '8726e21a993978c7ba086d3872e7608d7d5bfca646ca4aca459ffda844faa8b4  '$HOME'/.cache/torch/hub/checkpoints/955717e8-8726e21a.th' | sha256sum --check
```

Путь и сумму задают `TRANSCRIPTION_SEPARATION_CHECKPOINT_PATH` и
`TRANSCRIPTION_SEPARATION_CHECKPOINT_SHA256`.

При ошибке результат явно переходит в `speech_only` (по умолчанию) или
`original_ducked`, заданный `TRANSCRIPTION_BACKGROUND_FALLBACK`. RU-дорожка
содержит выделенный фон и синтез, а плеер выключает оригинальную дорожку, чтобы
английская речь не звучала дважды.

В режиме перевода видео Whisper использует VAD и
`condition_on_previous_text=false`: на контрольном ролике перенос предыдущего
контекста вставлял повтор фразы в участок 85 с, а в финальной паузе появлялась
несуществующая речь. Регрессионная проверка с настоящим Whisper через HTTP:

```bash
VOICEOVER_TEST_VIDEO=/absolute/path/to/rust-video.mp4 .venv/bin/python -m pytest tests/test_voiceover_api.py -k repeated_asr_context
```

Qwen получает нейтральную инструкцию произнесения одного основного варианта.
Ускорение готового WAV по-прежнему ограничено 1,5×; длительность результата
измеряется после синтеза.

### Корневой .env

Обычный запуск `npm run dev --workspace @daevox/transcription-backend` автоматически
читает `.env` из корня монорепозитория. Примеры настроек CosyVoice, GPU и локальной LLM
перечислены в корневом `.env.example`; `export` больше не требуется.
Переменные окружения процесса имеют приоритет над `.env`. Посторонние настройки
других приложений игнорируются. Относительные пути `DATA_DIR`, путей интерпретаторов и моделей
Qwen/Chatterbox/CosyVoice, исходников CosyVoice, `SILERO_PATH` и образцов голосов
с префиксом `TRANSCRIPTION_` разрешаются относительно `apps/transcription-backend`.
Исключение — `TRANSCRIPTION_SEPARATION_CHECKPOINT_PATH`: раскрывает `~`, а относительный
путь считается от рабочего каталога процесса; для него предпочтителен абсолютный путь.
После изменения `.env` перезапустите backend.

## Диагностика перевода видео

В `<TRANSCRIPTION_DATA_DIR>/voiceovers/<id>/processing.jsonl`
сохраняется подробный журнал в формате JSON Lines: время UTC, состояние записи,
параметры и запуск каждого worker, события stdout, stderr, длительности и ошибки.
Для LLM записываются полные запросы и ответы, идентификаторы запросов и попытки.
Журнал остаётся рядом с исходником после сборки видео и удаляется вместе с записью;
счётчик размера записи включает сохранённые промежуточные медиа. Секреты в
структурированных полях маскируются,
окружение процесса не записывается. Текст видео и ответы моделей сохраняются полностью.

Проверяющая модель и эвристики качества не используются. Если модель не вернула
непустой текст после трёх попыток, фраза явно помечается как отсутствующая.
Журнал создаётся при дальнейшей обработке; ответы прошлых запусков восстановить нельзя.

## Запуск и повторная озвучка

В форме видео включена автоматическая озвучка: `auto_synthesize: true` в запросе
создания запускает синтез с автоматически назначенными голосами после подготовки.
Без этого параметра API сохраняет прежнюю остановку на выборе голосов.
Для завершённого или неполного видео можно изменить назначения голосов
и вызвать `synthesize` с новой ревизией и новым ключом запроса: повторяется
только озвучка и сборка, без распознавания.

`GET /trancription-api/voiceover-devices` возвращает доступные GPU (UUID и название).
Поля `asr_gpu` и `tts_gpu` при создании видео выбирают устройства для этой записи;
разметка спикеров использует GPU распознавания. Если поля не заданы, применяются
настройки сервера. Выбор сохраняется в записи и в диагностическом журнале.

Прогресс единого этапа `dubbing` считается по фразам, успешно прошедшим подгонку.
Повторный синтез не увеличивает счётчик готовности. Статус `incomplete` не показывает
ложные 100%. Внутренние этапы и история каждой фразы доступны в деталях. Таймеры
этапов обновляются во время работы; общее время исключает загрузку файла
и ожидание выбора пользователя, но включает повторную озвучку.

Сборка публикует прогресс `rendering` для подготовки аудиодорожки и видео.
Совместимые потоки MP4 копируются без перекодирования; при несовместимом контейнере
используется H.264/AAC fallback. Окончательные 100% появляются после успешного FFmpeg.

### Просмотр во время озвучки

После появления примерно 20 секунд непрерывно готового звука доступен плеер,
не дожидающийся завершения всех фраз. `preview.available_seconds` отражает длину
опубликованного участка, `preview.complete` — завершение потока. Для видео короче
20 секунд просмотр открывается после подготовки всей дорожки.

Один FFmpeg-процесс кодирует поступающую временную шкалу в HLS EVENT-сегменты по
4 секунды, с тем же режимом фона. Плейлист публикуется атомарно с `no-store`,
сегменты неизменяемы. Каждый запуск получает отдельное поколение превью.
Плеер показывает готовую длительность, ждёт у её границы и продолжает после
поступления новых сегментов. Открытый поток сохраняется при финальной сборке;
скачивание полной русской дорожки доступно после её завершения.
