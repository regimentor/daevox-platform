# Daevox Platform

Daevox Platform развивается как платформа для agentic-задач. Сейчас это локальное приложение
с веб-интерфейсом для Telegram-секретаря, транскрибации записей и перевода видео с русской озвучкой.
Общие чаты с агентами и среда выполнения произвольных agentic-задач остаются целевым направлением.

## Реализованные возможности

### Telegram-секретарь

На странице `/telegram` пользователь подключает личный Telegram-аккаунт через QR-код и пароль
2FA. Сессия сохраняется между запусками; доступны отключение и повторное подключение.
Отдельная учётная запись Daevox для этого не требуется.

- Наблюдение за выбранными Telegram-чатами, импорт доступной истории за последние 30 дней
  и сохранение сообщений в SQLite-архив.
- Дневные саммари с постоянной очередью обработки, прогрессом и повтором ошибок,
  а также разовые сводки по запросу. Генерация использует локальный `llama-server`.
- Автоответчик выбранного Telegram-чата: ответы на новые сообщения на основе готового
  дневного саммари, обозначение авторства ИИ, очередь отправки и защита от дублей.
  Автоответчик работает на backend без открытой вкладки; состояние и проблемы доставки видны в UI.

Подготовка Telegram, базы и локальной модели описана в
[README backend](../apps/backend/README.md).

### Транскрибация

Страница `/transcription` принимает файл или публичную запись YouTube и создаёт транскрипт
с временными метками и метками спикеров. Для русского используется GigaAM-v3, для английского —
Whisper large-v3, для определения спикеров — pyannote Community-1. Результат доступен в TXT и JSON.

Распознавание и определение спикеров выполняются в отдельных процессах на NVIDIA GPU.
Запуск API и проверка состояния не загружают модели: обработку инициирует пользователь.
При отмене сохраняется уже принятый текст.

### Перевод видео с озвучкой

Страница `/voiceover` принимает английское видео с аудио или публичную завершённую запись YouTube.
После распознавания и определения спикеров сервис переводит фразы на русский через локальную LLM,
синтезирует речь и подгоняет её по времени исходной записи.

- Автоматическое назначение голосов с возможностью изменить их и повторить озвучку.
- Редактирование текста озвучки и повтор отдельной фразы с сохранением остальных результатов.
- Сохранение библиотеки записей, готового видео и отдельной русской аудиодорожки.
- Просмотр готовой части видео во время озвучки через потоковое превью.
- Отображение неполного результата и ошибок отдельных фраз, подробный журнал обработки.

Транскрибация и перевод используют один общий активный слот обработки. Внутри озвучки
перевод и синтез разных фраз перекрываются, а подгонка идёт в исходном порядке.
Поддерживаются Silero, Qwen, Chatterbox и CosyVoice; CosyVoice может выполнять два синтеза параллельно.
Требования к GPU, подготовка моделей и настройки перевода и синтеза речи описаны в
[README transcription-backend](../apps/transcription-backend/README.md).

## Компоненты и границы ответственности

Монорепозиторий управляется через npm workspaces. Веб-клиент и два backend запускаются отдельно.

| Workspace                                                                  | Ответственность                                                                                   |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| [`@daevox/web-client`](../apps/web-client/README.md)                       | Веб-интерфейс на React Router, Vite и Mantine: Telegram, транскрибация и озвучка.                 |
| [`@daevox/backend`](../apps/backend/README.md)                             | Node.js backend на `@daevox/framework`: Telegram-сессия, секретарь, саммари и автоответчик.       |
| [`@daevox/transcription-backend`](../apps/transcription-backend/README.md) | Python/FastAPI-сервис: обработка медиа, GPU-процессы, транскрипты и библиотека озвученных видео.  |
| [`@daevox/telegram-contract`](../packages/telegram-contract/)              | Общие DTO Telegram API для backend и веб-клиента.                                                 |
| [`@daevox/db`](../packages/db/README.md)                                   | Схема SQLite и доступ через Drizzle к архиву Telegram, очереди саммари и состоянию автоответчика. |
| [`@daevox/tdlib`](../lib/tdlib/README.md)                                  | Типизированный клиент TDLib на Node.js 26 с native FFI.                                           |
| [`@daevox/framework`](../lib/framework/README.md)                          | HTTP, WebSocket, события приложения, фоновые `Job` в Worker Pool и scheduled tasks.               |

В локальной разработке веб-клиент слушает `127.0.0.1:5173`. Vite направляет `/api/*`
в основной backend на `127.0.0.1:3000`, а `/trancription-api/*` — в сервис медиа
на `127.0.0.1:3001`. Написание `trancription-api` соответствует текущему API.
Основной backend предоставляет `GET /healthcheck`, сервис медиа — `GET /trancription-api/health`.

Архив Telegram по умолчанию хранится в `db/daevox.sqlite`; его схема применяется отдельно
командой `npm run db:push`. Сервис медиа владеет собственными результатами в `data/`,
включая `voiceovers.sqlite3` и файлы озвучки. Telegram-сессия хранится в отдельно настроенных
каталогах TDLib. Модели LLM запускаются отдельно от приложений.

Framework уже используется основным backend: scheduled tasks обновляют каталог Telegram-чатов
и запускают обработку дневных саммари через Worker Pool. Сервис медиа использует собственный
Python runtime и не зависит от framework.

## Целевые возможности

Следующие возможности пока не представлены как реализованные пользовательские сценарии:

- Чаты Daevox с персистентной памятью пользователя между разговорами, веб-поиском,
  вызовами инструментов и запуском субагентов.
- Agentic harness — общая среда выполнения и оркестрации agentic-задач пользователя.
- Создание пользователем agentic-задач, запускаемых по заданному расписанию.

Главная страница веб-клиента пока служит стартовым экраном. Telegram-чаты и их архив
не являются чатами Daevox и памятью пользователя. Существующие scheduled tasks обслуживают
конкретные функции backend; пользовательский интерфейс запланированных agentic-задач ещё предстоит создать.

## Запуск и проверки

Общие команды находятся в [корневом README](../README.md), подробная подготовка — в README
соответствующих сервисов. `npm run verify` запускает предусмотренные workspace проверки;
браузерные e2e и проверки с реальными GPU-моделями запускаются отдельно по инструкциям приложений.
