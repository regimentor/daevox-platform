# Встроенный WebSocket-протокол сообщений

<!-- adr-contract:websocket.protocol -->

ADR 0007 заменяется встроенным версионированным протоколом `daevox.v1`: все WebSocket-контроллеры публикуются через единый endpoint приложения, а текстовые JSON-сообщения маршрутизируются по обязательной паре `controller` и `event`. Контроллеры объявляют статические `name` и `events`, lifecycle hooks принадлежат конфигурации `Application`, а экземпляр найденного контроллера создаётся для каждого сообщения. Это отказывается от конкурирующей path-based адресации, raw-сообщений и lifecycle-контроллеров в пользу единственного коробочного контракта фреймворка.

Протокол не является RPC: ответ обработчика необязателен, наследует адрес входящего сообщения и не имеет correlation ID; server push пока не поддерживается. Фреймворк создаёт отдельные `clientId` и `sessionId` для каждой сессии, не выполняет авторизацию и не объединяет соединения одного пользователя. Нарушения протокола получают стабильные машинные коды, когда адрес сообщения известен, либо закрывают соединение стандартным WebSocket close code.

## Последствия

- Изменение несовместимо с `static path`, `onMessage`, controller lifecycle hooks, binary payloads и `clientSessions` из ADR 0007; compatibility mode не поддерживается.
- Клиент обязан согласовать `Sec-WebSocket-Protocol: daevox.v1` и передавать только строго проверяемые JSON-объекты `{ controller, event, body }` без дополнительных полей.
- `Application` сохраняет владение transport, session store и lifecycle; контроллеры не получают raw socket.
- Реализация остаётся на встроенных API Node.js без runtime-зависимостей согласно ADR 0001.
