# Карта публичного interface фреймворка

Эта карта направляет агента к минимальному набору контекста перед изменением поведения. Generated
типы находятся в [`docs/API.md`](../API.md), их окончательный состав задаёт
[`src/index.ts`](../../src/index.ts), архитектурные решения — в [`docs/adr/`](../adr/), а
фактическое поведение подтверждают публичные seam-тесты.

## Маршрутизация

- Регистрация, `listen()`, `close()` и владение ресурсами: [Application](application.md).
- HTTP-контроллеры, HTTP-маршруты, контекст и ответы: [HTTP](http.md).
- `daevox.v1`, сессии, lifecycle и server push: [WebSocket](websocket.md).
- Адресуемая fire-and-forget доставка и FIFO mailbox: [внутренние события](application-events.md).
- `Job`, Worker, очередь, отмена и тайм-ауты: [фоновые задачи](jobs.md).
- Порядок `(ctx, next)`, short-circuit и transport-specific ошибки: [middleware](middleware.md).
- Поиск error-класса по операции и transport-эффекту: [карта ошибок](errors.md).

Если изменение затрагивает несколько веток, прочитайте каждую соответствующую страницу. ADR,
указанные на capability-странице, имеют приоритет над её кратким резюме.

## Рабочий цикл агента

1. Откройте capability-страницу и связанные ADR.
2. Сверьте точные типы через [`docs/API.md`](../API.md), public export в
   [`src/index.ts`](../../src/index.ts) и исходный модуль по ссылке от сущности.
3. Изменяйте поведение через публичный seam, сохраняя перечисленные инварианты.
4. Запустите указанные seam-тесты, затем `npm run docs:build` и `npm run docs:check`.

Работа завершена, когда изменённый interface описан, каждый затронутый инвариант подтверждён
тестом через публичный seam, generated-документация актуальна и связанные ADR не противоречат коду.
