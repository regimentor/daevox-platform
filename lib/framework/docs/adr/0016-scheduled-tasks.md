# Запланированные задачи Application

По согласованной [концепции](../../.scratch/scheduled-tasks/map.md) Application регистрирует
отдельный артефакт ScheduledTask: прямой наследник `ScheduledTaskBase` с собственными `cron`
и prototype `run(appState, { signal }): Promise<void>`. Каждый запуск создаёт новый экземпляр
в основном потоке; CPU-работу задача передаёт Job Runner. Пока Promise run не завершён,
новые срабатывания этой регистрации пропускаются без очереди, а другие регистрации и Application
независимы. Это сохраняет stateless-модель и ограничивает накопление работы при перегрузке.

Шестипольный числовой cron использует локальный часовой пояс, зафиксированный при активации
Application. Необходимости сторонней runtime-зависимости нет: календарь реализован на Date и Intl.
Проверка возможной даты выполняется до публикации; ближайший будущий момент вычисляется по
календарным дням и смещениям часового пояса с сохранением обоих абсолютных моментов повторённого
местного времени. Задержанные срабатывания объединяются; история остановленного приложения
не восстанавливается. Отдельный cron-engine и каталог расписаний не являются публичным API.

## Дополнение ADR 0011 и ADR 0015

Новые startup/runtime-методы сохраняют атомарную регистрацию и закрывают её при начале close.
Идентичность задачи определяется constructor, а имя класса используется только для диагностики.
Расписания включаются после успешного startup; ошибка startup или начавшийся close не разрешают
их активацию. В начале close отменяются активные сигналы и останавливаются расписания.

<!-- adr-contract:application.shutdown-order -->

Завершение прекращает новый HTTP- и WebSocket-ввод, останавливает расписания и отменяет сигналы активных ScheduledTask. После закрытия WebSocket-сессий приложение последовательно ждёт HTTP- и WebSocket-операции, затем ScheduledTask, запечатывает EventSender, опустошает mailboxes и закрывает Job Runner. Бюджеты `http.shutdownTimeout`, `websocket.shutdownTimeout`, `scheduledTasks.shutdownTimeout`, `events.shutdownTimeout` и `jobs.shutdownTimeout` независимы и складываются.

<!-- adr-contract:scheduled-tasks.execution -->

Каждый допущенный запуск создаёт новый ScheduledTask с DI `{ jobRunner, events, websocket }` и общим AppState в аргументе run. Один constructor в одном Application не выполняется параллельно самому себе; пропуски не образуют очередь. Ошибки constructor/run наблюдаются без обёртки через onError; ошибка наблюдателя выводится в console.error без ожидания его Promise. Общий shutdownTimeout по умолчанию 30000 мс не отклоняет close: незавершённые задачи однократно получают ScheduledTaskShutdownTimeoutError, поздние rejection перехватываются без повторного уведомления.

Пользовательский код основного потока не может быть принудительно прерван таймером. До конца
фазы ScheduledTask доступны events и Job Runner; доступность WebSocket-сессий не продлевается.
