# Выполнение запросов и жизненный цикл

Обработчики контроллеров всегда выполняются в основном потоке приложения, а фоновые задачи передаются `Job Runner` в пул Worker. `IncomingMessage`, `ServerResponse` и socket не входят в `RequestContext`; результаты всех обработчиков проходят единый процесс нормализации ответа. Отмена и тайм-ауты должны иметь явную семантику и обязательную очистку ресурсов.

HTTP transport запускается однократным `Application.listen()`: после начала запуска каталог HTTP-маршрутов неизменяем, а ошибка запуска переводит приложение в необратимое failed-состояние. `Application.close()` необратимо завершает всё приложение: сначала прекращает приём HTTP-запросов, ограниченно ждёт активные запросы, затем закрывает принадлежащий приложению `Job Runner`. Такая модель исключает частичный перезапуск компонентов с уже закрытыми зависимостями и сохраняет детерминированный каталог HTTP-возможностей на всём времени работы.
