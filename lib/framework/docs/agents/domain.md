# Документация предметной области

Правила использования документации предметной области инженерными навыками при изучении кодовой базы.

## Что читать перед исследованием

- Корневой файл `CONTEXT.md`.
- Связанные с исследуемой областью архитектурные решения из `docs/adr/`.

Если этих файлов нет, следует продолжить работу без предупреждений и без предложения создать их заранее. Навык `/domain-modeling` создаёт их по мере необходимости, когда определяются термины или принимаются решения.

## Структура файлов

Репозиторий использует одноконтекстную структуру:

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## Использование терминов глоссария

Если результат работы называет понятие предметной области — например, в заголовке задачи, предложении рефакторинга, гипотезе или названии теста, — следует использовать термин из `CONTEXT.md`. Нельзя заменять его синонимами, которые глоссарий явно отвергает.

Если нужного понятия нет в глоссарии, следует проверить, действительно ли оно относится к проекту, либо отметить пробел для `/domain-modeling`.

## Конфликты с ADR

Если предлагаемая работа противоречит существующему ADR, конфликт следует обозначить явно, а не переопределять решение молча.
