# Отправка WebSocket-сообщений из HTTP-контроллера

Status: accepted — архитектура согласована в grilling-сессии; реализация требует пересмотра затронутых положений ADR 0008.

## Назначение

Добавить возможность отправлять server push-сообщения из HTTP-контроллера в одну или несколько активных WebSocket-сессий, не передавая контроллеру raw socket и не заставляя фреймворк хранить связь между прикладным `userId` и WebSocket-сессиями.

## Идентификаторы и ответственность

Фреймворк назначает каждой новой WebSocket-сессии `sessionId` и первоначальный случайный `clientId`.

`websocket.onConnect(ctx)` может вернуть стабильный прикладной `clientId`:

- `undefined` — используется сгенерированный `ctx.clientId`;
- непустая строка — используется возвращённое значение;
- другое значение — ошибка handshake HTTP 500, наблюдаемая через `websocket.onError`.

Сгенерированный идентификатор доступен в `ctx.clientId` во время `onConnect`. После завершения hook итоговый `clientId` передаётся в контексты WebSocket и `onDisconnect`.

Несколько активных WebSocket-сессий могут иметь один `clientId`. Фреймворк хранит только активный индекс:

```text
clientId → Set<sessionId>
```

Связь прикладного `userId` с `clientId`, разбор cookie или другого HTTP-session header, а также обновление внешнего стора выполняет приложение. Рекомендуемый lifecycle внешнего стора:

```text
onConnect    → приложение разбирает headers, получает/создаёт clientId и обновляет userId → clientId
onDisconnect → приложение обновляет внешний стор; фреймворк удаляет clientId → sessionId
```

Повторное использование `clientId` после закрытия всех его сессий разрешено.

## Публичный интерфейс

HTTP-контроллер получает application-wide sender как `this.websocket`:

```js
this.websocket.send({ clientId, sessionIds }, { controller, event, body });
```

`sessionIds` необязателен:

- `{ clientId }` — отправка во все активные сессии клиента;
- `{ clientId, sessionIds: ['session-a', 'session-b'] }` — отправка только в выбранные сессии;
- пустой массив — отправка ни в одну сессию.

Дубликаты в `sessionIds` устраняются. Сессия, не принадлежащая `clientId`, и закрытая сессия пропускаются.

Результат:

```js
{
  (sent, skipped);
}
```

Неизвестный `clientId` является ошибкой `WebSocketClientNotFoundError`. Когда закрывается последняя сессия клиента, его пустая запись удаляется из активного индекса, поэтому последующая отправка по этому `clientId` также считается обращением к неизвестному клиенту. Если все сессии исчезли после начала конкретного вызова `send`, результатом этого вызова может быть `{ sent: 0, skipped: 0 }`.

## Исходящее сообщение

Сообщение использует существующий envelope `daevox.v1`:

```json
{
  "controller": "notifications",
  "event": "updated",
  "body": { "id": 42 }
}
```

Фреймворк проверяет wire-имена, строгую JSON-совместимость `body` и ограничение `maxPayload`. Ошибка проверки вызывает `InvalidWebSocketSendError` синхронно и не отправляется WebSocket-клиенту.

Исходящие события не обязаны быть зарегистрированы как входные события WebSocket-контроллера. Приложение самостоятельно поддерживает договорённость с клиентом.

## Семантика доставки

`send` является синхронным best-effort вызовом. `sent` означает, что frame принят локальным socket для записи, но не означает доставку, чтение или обработку клиентом.

`socket.write() === false` означает backpressure, а не отказ отправки, и не уменьшает `sent`. Ошибка socket, возникшая асинхронно после возврата `send`, передаётся в `websocket.onError`; уже возвращённый результат не изменяется.

Новые отправки во время закрытия приложения не гарантируются и могут быть пропущены. Retry, persistence, client acknowledgements, глобальный порядок между HTTP-отправками и WebSocket-ответами, а также отправка из `Job` не входят в задачу.

## Вне scope

- хранилище `userId → clientId` и его консистентность;
- встроенная авторизация и разбор HTTP-сессионных идентификаторов;
- распределённая или межпроцессная маршрутизация;
- очереди, retry и гарантированная доставка;
- отправка из фоновых `Job`;
- отдельный протокол push и correlation ID;
- обязательная декларация исходящих событий.
