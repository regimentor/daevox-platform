# Покрыть гонки отмены, timeout, завершения задачи и close

Добавить детерминированные race-тесты для конкурирующих терминальных событий одного HTTP-запроса или запуска задачи.

## Требования

- Создать барьерные job-fixtures, позволяющие отдельно подтвердить постановку в очередь, начало выполнения, подготовку результата и разрешение завершения.
- Проверить попарные гонки: результат/отмена, результат/timeout, отмена/timeout, падение Worker/отмена, падение Worker/timeout и `close()` с каждым из этих событий.
- Проверить отмену HTTP-клиентом во время чтения тела, выполнения HTTP-обработчика, ожидания задачи и записи ответа.
- Проверить закрытие WebSocket-сессии во время WebSocket-обработчика и завершение обработчика после закрытия сессии.
- Проверить конкурентные `listen()`/`close()` в допустимых состояниях lifecycle, включая ошибку запуска.
- Для каждой гонки утверждать ровно один наблюдаемый исход, одно освобождение ресурсов и отсутствие позднего необработанного rejection.
- Повторять сценарии с разным детерминированным порядком разрешения барьеров и достаточным числом итераций.
- Не считать произвольную задержку доказательством наступления состояния; использовать события, сообщения Worker или явно доступные тестовые барьеры.

## Критерии приёмки

- Каждый допустимый порядок событий имеет явный ожидаемый результат.
- Задача не разрешается и не отклоняется повторно на уровне наблюдаемого публичного Promise.
- Освободившийся слот пула используется следующей задачей, Worker восстанавливается при необходимости.
- Не возникают `unhandledRejection`, `uncaughtException`, двойной `onDisconnect` или запись HTTP-ответа после закрытия.
- Набор имеет ограниченное время выполнения и сообщает номер итерации и порядок событий при сбое.
- `npm run check` проходит.

## Comments

Реализовано через TDD на подтверждённых публичных швах. Добавлены команда
`npm run test:races`, системный набор `test/races.test.js` и Worker-fixture с
`SharedArrayBuffer`-барьерами начала выполнения, подготовки результата и разрешения
завершения. По три раза выполняются оба порядка для результата/отмены, результата/timeout,
отмены/timeout, падения Worker/отмены, падения Worker/timeout и `JobRunner.close()` с
результатом, отменой, timeout и падением Worker. Для каждого запуска проверяются одно
settlement публичного Promise и повторное использование слота или восстановленного Worker.

Реальными соединениями проверена отмена HTTP-клиентом во время чтения тела,
HTTP-обработчика, ожидания задачи и передачи ответа, а также закрытие WebSocket-сессии во
время обработчика, его позднее завершение и однократный `onDisconnect`. Покрыты
конкурирующие `Application.listen()`/`close()`, закрытие до запуска и ошибка запуска на
занятом порту. Профиль и воспроизведение описаны в `docs/system-testing.md`; произвольные
задержки не используются как доказательство состояния. `npm run check` проходит (117
тестов).
