# Добавить black-box e2e и проверку установки npm tarball

Создать внешний consumer-fixture, который устанавливает собранный tarball и проверяет Daevox только через опубликованный публичный API и реальные сетевые соединения.

## Требования

- Собирать пакет командой `npm pack` во временный каталог и устанавливать tarball в чистый временный ESM-проект.
- Проверять состав tarball: необходимые файлы присутствуют, тесты и служебные scratch-файлы не публикуются без необходимости, runtime-зависимости отсутствуют.
- Запускать consumer-приложение отдельным процессом, не импортируя исходники через относительные пути репозитория.
- Зарегистрировать HTTP- и WebSocket-контроллеры, запустить приложение на ephemeral-порту и выполнить реальные HTTP-запросы и WebSocket handshake/messages.
- Проверить сквозной сценарий HTTP-запрос → HTTP-контроллер → задача → Worker → HTTP-ответ.
- Проверить одновременную работу HTTP и `daevox.v1` на одном listener.
- Проверить ожидаемые публичные ошибки и успешное завершение consumer-процесса после `Application.close()`.
- Добавить быструю npm-команду для локального и CI-запуска e2e-проверки.
- Гарантированно удалять временные проекты и завершать дочерние процессы при успехе, ошибке и timeout.

## Критерии приёмки

- Проверка проходит из tarball без доступа к внутренним импортам и рабочему дереву проекта.
- Ошибка упаковки, отсутствующий публичный файл или неработающий импорт обнаруживаются до сетевых сценариев.
- HTTP, WebSocket и Worker проверяются в одном внешнем приложении.
- После проверки не остаются listener, socket, Worker или дочерний процесс.
- Все тестовые файлы имеют расширение `.js`, новые runtime-зависимости отсутствуют, `npm run check` проходит.
