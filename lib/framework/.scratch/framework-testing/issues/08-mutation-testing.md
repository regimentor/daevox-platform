# Внедрить mutation testing тестовой базы

Добавить воспроизводимую оценку того, обнаруживают ли существующие тесты изменения поведения в наиболее рискованных компонентах фреймворка.

## Требования

- Выбрать mutation runner с поддержкой ESM и Node.js 26 либо реализовать минимальный проектный harness; решение и необходимость dev-зависимостей кратко обосновать.
- Не добавлять runtime-зависимости и не включать mutation-инструменты в npm tarball.
- Начать с модулей нормализации HTTP-ответа, HTTP-маршрутизации, WebSocket-протокола и терминальных состояний Worker Pool.
- Исключать механические или эквивалентные mutants только с зафиксированным объяснением, а не для искусственного повышения score.
- Сохранять отчёт с killed, survived, timeout и no-coverage mutants, сгруппированными по модулю.
- Для каждого осмысленного survived mutant либо добавить тест, либо оформить объяснение, почему изменение эквивалентно.
- Добавить быстрый инкрементальный режим для изменённых модулей и полный scheduled/release-режим.
- Зафиксировать начальную baseline mutation score и постепенно повышаемый gate; не требовать немедленно 100%.

## Критерии приёмки

- Контрольные изменения сравнений границ, кодов ошибок и порядка cleanup обнаруживаются тестами.
- Отчёт позволяет перейти от survived mutant к конкретной строке и недостающему сценарию.
- Повторный прогон на неизменном коде даёт стабильную классификацию mutants.
- Mutation testing запускается отдельной npm-командой и не делает обычный `npm run check` неприемлемо медленным.
- Любые добавленные тесты проверяют наблюдаемое поведение, а не детали реализации только ради убийства mutant.
- `npm run check` проходит.

## Comments

Реализован минимальный ESM harness без новых зависимостей: 19 проверенных мутаций покрывают
границы нормализации HTTP-ответа, сопоставление HTTP-маршрутов, коды и размер сообщений
`daevox.v1`, терминальные состояния, FIFO и cleanup Worker Pool. Каждый mutant запускается в
изолированной временной копии; V8 coverage разделяет `survived` и `no-coverage`. JSON- и
Markdown-отчёты группируются по модулю и содержат путь, строку и проверяемый сценарий.

Добавлены быстрый `npm run mutation:changed` (с `MUTATION_BASE` для CI) и полный
`npm run mutation:full` для scheduled/release. Начальная baseline и повышаемый gate сохранены
в `mutation/baseline.json`, обоснование runner и исключения эквивалентных/mechanical mutants —
в `docs/mutation-testing.md`. Добавлены наблюдаемые тесты обеих границ HTTP status code и
порядка завершения FIFO. Полный прогон классифицировал 16 mutants как killed и 3 как timeout;
survived и no-coverage отсутствуют, начальный score 100% проходит gate 80%.
