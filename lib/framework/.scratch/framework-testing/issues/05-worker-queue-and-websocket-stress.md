# Добавить stress-тест очереди задач и WebSocket-сессий

Определить пределы устойчивой работы ограниченной очереди задач и большого числа WebSocket-сессий, а также характер контролируемой деградации после насыщения.

## Требования

- Добавить настраиваемый профиль постепенного роста нагрузки с фиксированными ступенями и длительностью каждой ступени.
- Для пула проверить короткие задачи, длинные задачи и смесь длительностей при `poolSize` 1, около числа CPU и выше числа CPU.
- Довести очередь до `queueSize`, проверить FIFO, предсказуемое отклонение сверх лимита и восстановление после разгрузки.
- Для WebSocket проверить скорость handshake, большое число idle-сессий, поток сообщений по одной сессии и параллельные сообщения по многим сессиям.
- Проверить массовое одновременное отключение и последующее переподключение сессий.
- Добавить смешанный профиль HTTP + WebSocket + задачи, чтобы насыщение пула не блокировало обычные HTTP-ответы и независимые WebSocket-сессии сверх согласованных порогов.
- Ограничить максимальные concurrency, память и длительность безопасными явными параметрами; предусмотреть аварийное завершение сценария.
- Сохранять throughput, latency, ошибки, queue wait, RSS, heap, event-loop lag и число соединений/Worker на каждой ступени.

## Критерии приёмки

- Тест определяет последнюю устойчивую ступень и первую ступень деградации, не полагаясь на один случайный пик.
- Переполнение очереди и payload/session ошибки выражаются ожидаемыми публичными результатами, без падения процесса.
- После снижения нагрузки latency, очередь и память возвращаются в документированный диапазон восстановления.
- Последовательность событий одной WebSocket-сессии сохраняется, разные сессии продолжают выполняться независимо.
- Сценарий запускается отдельной npm-командой и не входит в обычный `npm run check`.

## Comments

Реализован отдельный stress-сценарий с командами `npm run stress` и
`npm run stress:smoke`. Профили покрывают ступенчатую нагрузку Worker Pool,
FIFO/переполнение/восстановление очереди, handshake/idle/message/reconnect WebSocket-сессий,
ошибки публичного протокола и смешанную HTTP + WebSocket + Job нагрузку. JSON-артефакт
сохраняет метрики каждой ступени, границы устойчивости и результат recovery; safety-лимиты и
аварийное завершение заданы явно. Полный локальный прогон на 14 CPU проверил `poolSize`
`1/14/15` и завершился успешно после применения документированного recovery gate.
