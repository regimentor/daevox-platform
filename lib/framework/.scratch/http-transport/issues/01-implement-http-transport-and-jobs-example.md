# Реализовать HTTP transport и example запуска задач

Реализовать согласованный контракт из [`../spec.md`](../spec.md) на базе `node:http`, связать выполнение HTTP-обработчиков с существующими `HttpRouter` и `JobRunner` и добавить example-приложение запуска задач.

## Требования

- Добавить строгую конфигурацию `http`, однократный `Application.listen()` и согласованный необратимый жизненный цикл приложения.
- Реализовать ограниченный graceful shutdown HTTP transport перед закрытием `Job Runner`.
- Расширить `HttpControllerBase` контрактом `{ jobRunner }` и создавать новый HTTP-контроллер для каждого сопоставленного запроса.
- Сформировать `HttpRequestContext` без раскрытия `IncomingMessage`, `ServerResponse` и socket.
- Реализовать ограниченное чтение JSON, отмену при отключении клиента и согласованные инфраструктурные HTTP-ошибки.
- Реализовать `404`, `405` с `Allow`, неявный `HEAD`, автоматический `OPTIONS` и приоритет явных HTTP-маршрутов.
- Реализовать строгий `HttpResponse`, полную сериализацию до записи заголовков и владение framing-заголовками.
- Добавить публичные `HttpError`, `InvalidHttpOptionsError` и `ApplicationStateError`, а также безопасный путь неожиданных ошибок через `onError`.
- Добавить `examples/jobs-http/` с `JobsController`, `SumJob`, `main.js` и npm-командой `example:jobs-http`.
- Обновить README: актуальный `listen()` API, форма HTTP-ответа, запуск example и пример HTTP-запроса.
- Добавить unit- и integration-тесты на каждый раздел спецификации, включая реальные HTTP-запросы, Worker-задачу, отмену и отсутствие утечек ресурсов.
- Использовать только JavaScript в `.js` и встроенные возможности Node.js; runtime-зависимости не добавлять.
- Добиться успешного выполнения `npm run check`.

## Критерии приёмки

- Поведение соответствует всем разделам `spec.md` и существующим ADR 0002, 0003, 0005 и 0006.
- `Application.listen()` разрешает `port: 0`, возвращает фактический адрес и не допускает повторный запуск даже после ошибки bind.
- После начала запуска каталог HTTP-маршрутов неизменяем, а приложение без контроллеров корректно отвечает `404`.
- Каждый запрос получает новый HTTP-контроллер и новый `HttpRequestContext`; реальный внутренний `JobRunner` доступен контроллеру только через конструкторную зависимость.
- HTTP transport не раскрывает транспортные объекты Node.js пользовательскому коду.
- Поддержанные запросы, ответы, ошибки, `HEAD`, `OPTIONS`, `405 Allow` и shutdown имеют детерминированную проверенную семантику.
- Example запускается документированной npm-командой и возвращает `{ "sum": 6 }` для входа `{ "values": [1, 2, 3] }`.
- После `await application.close()` процесс не удерживается HTTP-сервером, соединениями, timers или Worker.
- `npm run check` завершается успешно.
