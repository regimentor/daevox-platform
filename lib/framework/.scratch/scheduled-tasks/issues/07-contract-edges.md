## Question

Каким наблюдаемым поведением дополнить концепцию для четырёх случаев, найденных при
проверке полноты?

- Run возвращает обычное значение вместо Promise, несмотря на TypeScript-контракт.
- Пользователь задаёт shutdownTimeout: допустимы ли ноль, Infinity, дроби и отрицательные числа?
- OnError возвращает Promise, который не завершается: должно ли это задерживать расписание
  или Application.close()?
- Системные часы корректируются вперёд или назад: как применять объединение пропусков
  и исключать повторное срабатывание для того же абсолютного момента, сохраняя оба
  наступления местного времени при сезонном переводе часов?

Ответ должен дополнить существующие решения без изменения уже согласованных правил
идентичности задач, перекрытия run и кооперативного shutdown.

## Answer

Пользователь подтвердил все четыре уточнения.

- Если run возвращает обычное значение вместо Promise, это нарушение контракта.
  Framework сообщает TypeError через scheduledTasks.onError с phase run и контекстом
  соответствующего класса. Текущая попытка завершается, расписание продолжает работу.
- `scheduledTasks.shutdownTimeout` задаётся положительным целым числом миллисекунд
  не больше Number.MAX_SAFE_INTEGER. Ноль, отрицательные значения, дроби и Infinity
  недопустимы и отклоняются при создании Application. Значение по умолчанию — 30000 мс.
  Публичный путь настройки — `scheduledTasks.shutdownTimeout`.
- Framework не ожидает Promise, возвращённый onError. Наблюдатель не задерживает
  следующие запуски ScheduledTask и завершение Application.close(). Rejection наблюдателя
  по-прежнему перехватывается и выводится в console.error.
- При коррекции системных часов вперёд пропущенные срабатывания объединяются в одно
  по принятой политике пропусков и ограничения активного run.
- При коррекции часов назад уже обработанный абсолютный момент срабатывания не
  воспроизводится повторно. Совпадения местного времени при сезонном переводе часов
  сохраняют оба срабатывания, поскольку соответствуют разным абсолютным моментам.

## Comments

На вопросы о нарушении Promise-контракта, границах shutdownTimeout, асинхронном onError
и коррекции системных часов пользователь ответил утвердительно по каждому пункту.
