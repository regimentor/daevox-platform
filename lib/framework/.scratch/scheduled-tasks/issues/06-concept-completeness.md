## Question

Какие примеры и проверяемые сценарии доказывают, что концепция однозначна и готова к последующей спецификации?

Свести границы ScheduledTask и Job, пример запуска Job через расписание и пример другого прикладного сценария. Проверить, что принятые решения совместимы по типизации AppState, DI, времени, регистрации, ошибкам и shutdown. Выявить оставшиеся вопросы, не приступая к production-реализации или написанию окончательной спецификации.

## Answer

После разрешения пограничных случаев содержательных противоречий между решениями
карты не обнаружено. Пользователь принял следующие критерии будущей спецификации
и проверки реализации:

1. Два прикладных сценария: ScheduledTask ожидает Worker Job, передавая сериализуемый
   payload и signal; другая ScheduledTask выполняет асинхронную операцию через ресурс AppState
   без Job Runner. Оба сценария используют новый экземпляр на запуск.
2. Объявление и типизация: прямое наследование, собственные cron и prototype run,
   тип AppState согласуется с Application, constructor DI содержит три принятые capability,
   run с одним аргументом допустим; ошибки формы объявления и нарушение Promise-контракта
   имеют наблюдаемое поведение согласно решениям карты.
3. Регистрация и календарь: startup/runtime readiness, отсутствие немедленного запуска,
   атомарный отказ, повтор constructor и одинаковые имена разных классов; грамматика cron,
   невозможные даты, часовой пояс, сезонные переходы, задержки и коррекция системных часов.
4. Выполнение: отсутствие переиспользования экземпляра, запрет перекрытия одного класса,
   независимость разных классов и Application; Job без ожидания не продлевает активность run.
5. Ошибки и завершение: constructor/run errors, изоляция onError, остановка таймеров,
   сигнал отмены, общий бюджет фазы ScheduledTask, доступность events/Job Runner до её конца,
   timeout без отклонения close и перехват поздних rejection.

Это критерии для последующей спецификации и реализации, а не заявление о прохождении
тестов нового API: production ScheduledTask ещё не реализован.

Согласованная форма использования (прикладные MyAppState, RebuildIndexJob и метод
cache.refresh приведены как примеры; код не является runnable-артефактом):

```ts
class RebuildIndex extends ScheduledTaskBase {
  static cron = '0 */5 * * * *';

  async run(appState: MyAppState, { signal }: ScheduledTaskContext): Promise<void> {
    await this.jobRunner.run(RebuildIndexJob, { tenantId: appState.tenantId }, { signal });
  }
}

class RefreshCache extends ScheduledTaskBase {
  static cron = '0 * * * * *';

  async run(appState: MyAppState, { signal }: ScheduledTaskContext): Promise<void> {
    await appState.cache.refresh({ signal });
  }
}
```

Все вопросы карты разрешены. Концепция готова к передаче для последующего написания
спецификации; реализация и выбор cron-движка остаются за границами этой карты.
