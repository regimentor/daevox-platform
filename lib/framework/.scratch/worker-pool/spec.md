# Выполнение фоновых задач в пуле Worker

## Назначение

Добавить выполнение пользовательских фоновых задач в переиспользуемых потоках `node:worker_threads`. `Application` владеет инфраструктурой задач, но не раскрывает `JobRunner` или `WorkerPool` через публичные свойства и экспорты.

## Компоненты

### `Job`

- Реализуется публичным именованным экспортом из `lib/framework/Job.js`.
- Не допускает прямого создания экземпляра.
- Пользовательский класс задачи обязан напрямую наследовать `Job`; промежуточные базовые классы не допускаются.
- Для каждого запуска Worker создаёт новый экземпляр без аргументов.

### `JobRunner`

- Является внутренним компонентом приложения и не входит в пользовательский публичный API.
- Принимает класс задачи, проверяет его контракт и передаёт нормализованную работу в `WorkerPool`.
- Не управляет потоками, очередью или распределением работы.
- Предоставляет `run(JobClass, payload, options)` и возвращает Promise результата задачи.
- После начала закрытия не принимает новые задачи.

### `WorkerPool`

- Является внутренним компонентом и использует только встроенный `node:worker_threads`.
- Получает нормализованное описание работы с URL модуля, payload, сигналом и тайм-аутом; ничего не знает о переданном пользователем классе.
- Лениво создаёт Worker и увеличивает их количество не выше `poolSize`.
- Выполняет не больше одной задачи одновременно в каждом Worker.
- Переиспользует Worker после успешного выполнения и после исключения из `Job.run()`.
- Распределяет ожидающие задачи в порядке FIFO; приоритеты и автоматические повторные попытки отсутствуют.

### `Application`

- Создаёт и хранит единственный приватный `JobRunner`, владеющий единственным `WorkerPool`.
- Не позволяет внедрить пользовательский `JobRunner` или `WorkerPool`.
- Принимает настройки задач во вложенном объекте `jobs`.
- Предоставляет идемпотентный асинхронный `close()` для завершения принадлежащих приложению ресурсов.
- Будущий слой выполнения HTTP-обработчиков создаёт контроллер как `new HttpController({ jobRunner })`; создание контроллеров не входит в эту функциональность.

## Декларация задачи

```js
import { Job } from './lib/framework/Job.js';

export default class PdfJob extends Job {
  static metaUrl = import.meta.url;

  async run(payload, { signal }) {
    return { path: payload.path };
  }
}
```

Класс задачи обязан:

- напрямую наследовать `Job`;
- иметь собственное статическое data-поле `metaUrl`, содержащее абсолютный URL с протоколом `file:`;
- быть `default`-экспортом модуля, указанного в `metaUrl`;
- иметь собственный экземплярный метод-функцию `run`;
- не рассчитывать на аргументы конструктора.

Унаследованные `metaUrl` и `run`, статический `run`, accessor вместо data-поля и именованный экспорт вместо default не соответствуют контракту.

## Проверка контракта

- `JobRunner.run()` синхронно проверяет класс, прямое наследование, собственные `metaUrl` и `run`, а также options до изменения очереди.
- Worker импортирует модуль по `metaUrl` и повторно проверяет контракт его `default`-экспорта.
- Worker требует, чтобы `module.default.metaUrl` обозначал тот же URL, по которому загружен модуль.
- Повторная проверка в Worker считается окончательной: основной поток не импортирует модуль задачи для сравнения экспортов.

## Запуск и данные

```js
const result = await jobRunner.run(PdfJob, payload, {
  signal,
  timeout,
});
```

- `payload` является необязательным.
- `options` является необязательным объектом и допускает только `signal` и `timeout`.
- `signal`, если передан, обязан быть экземпляром `AbortSignal`.
- `timeout`, если передан, является конечным неотрицательным числом миллисекунд; `0` означает немедленный тайм-аут.
- При отсутствии `timeout` используется `defaultTimeout`; если он также отсутствует, время выполнения не ограничено.
- `Job.run()` получает payload и объект `{ signal }` с локальным для Worker `AbortSignal`.
- Результатом `JobRunner.run()` является значение, возвращённое или разрешённое `Job.run()`.
- Payload проверяется через structured clone до помещения в очередь. Результат также обязан поддерживать structured clone.
- Отдельный `transferList` и передача владения transferable-объектами не поддерживаются.
- Ошибка проверки класса или options выбрасывается синхронно. Ошибка клонирования, заполненная очередь и ошибки после принятия корректного вызова отклоняют возвращённый Promise.

## Конфигурация

```js
new Application({
  jobs: {
    poolSize: availableParallelism(),
    queueSize: 1000,
    defaultTimeout: undefined,
    terminationGracePeriod: 1000,
    shutdownTimeout: 30000,
  },
});
```

- Все интервалы задаются в миллисекундах.
- `poolSize` является положительным целым числом.
- `queueSize` является неотрицательным целым числом и ограничивает только ожидающие задачи; выполняющиеся задачи в лимит очереди не входят.
- `defaultTimeout` либо отсутствует, либо соответствует правилам `timeout` одного запуска.
- `terminationGracePeriod` и `shutdownTimeout` являются конечными неотрицательными числами.
- Неизвестные поля `jobs` отклоняются как неверная конфигурация.
- При отсутствии `jobs` используются все значения по умолчанию.

## Очередь и backpressure

- При наличии свободного Worker задача начинает выполняться без помещения в очередь.
- Если все Worker заняты, задача помещается в FIFO-очередь.
- Если число ожидающих задач уже равно `queueSize`, новая задача не принимается и её Promise отклоняется `JobQueueFullError`.
- При `queueSize: 0` допускается только немедленный запуск на свободном Worker.

## Отмена и тайм-аут

- Если внешний сигнал уже отменён или `timeout` равен `0`, задача не импортируется и не выполняется.
- Отмена ожидающей задачи удаляет её из очереди и отклоняет Promise `JobAbortedError`.
- Тайм-аут ожидающей или выполняющейся задачи отклоняет Promise `JobTimedOutError`.
- Для выполняющейся задачи пул сначала отправляет Worker команду отмены; локальный сигнал задачи становится aborted.
- Если задача не завершилась за `terminationGracePeriod`, пул принудительно завершает Worker.
- Принудительно завершённый Worker заменяется лениво либо немедленно, если в очереди есть работа.
- Завершение отменённой или просроченной задачи после принятия решения об отмене не меняет уже выбранный результат Promise.

## Ошибки Worker и задачи

- Если `Job.run()` выбрасывает или отклоняет ошибку, Promise отклоняется `JobExecutionError`, а Worker остаётся доступным для следующей задачи.
- Между потоками сохраняются доступные поля `name`, `message`, `stack` и цепочка `cause`; восстановленная ошибка задачи передаётся как `cause` ошибки `JobExecutionError`.
- Если Worker аварийно завершается или нарушает внутренний протокол, выполняющаяся задача отклоняется `WorkerTerminatedError`.
- Аварийно завершившийся Worker заменяется немедленно только при наличии ожидающей работы; иначе следующий Worker создаётся лениво.
- Неклонируемый результат отклоняет Promise `JobDataCloneError` и не считается ошибкой контракта класса.

## Завершение приложения

При первом вызове `application.close()`:

1. новые запуски отклоняются `JobRunnerClosedError`;
2. ожидающие задачи удаляются и отклоняются `JobAbortedError`;
3. выполняющимся задачам разрешается завершиться до истечения `shutdownTimeout`;
4. после истечения лимита оставшиеся Worker принудительно завершаются, а их задачи отклоняются `WorkerTerminatedError`.

Повторные и конкурентные вызовы `close()` используют тот же процесс завершения и не создают ошибку. После закрытия приложение и его `JobRunner` не могут быть запущены повторно.

## Кеширование и состояние модуля

- ESM-модуль задачи импортируется один раз в пределах каждого Worker и остаётся в его module cache.
- Каждый запуск создаёт новый экземпляр default-экспорта.
- Модульное состояние не разделяется между Worker и может сохраняться между задачами в одном Worker.

## Ошибки

Классы ошибок реализуются в `lib/framework/errors.js`, доступны прямым импортом и поддерживают `instanceof`:

- `InvalidJobError extends TypeError` — неверный класс или контракт задачи;
- `InvalidJobOptionsError extends TypeError` — неверные options запуска или конфигурация jobs;
- `JobDataCloneError extends Error` — payload или результат нельзя клонировать;
- `JobQueueFullError extends Error` — ограниченная очередь заполнена;
- `JobAbortedError extends Error` — задача отменена сигналом или закрытием приложения;
- `JobTimedOutError extends Error` — истёк тайм-аут задачи;
- `JobExecutionError extends Error` — `Job.run()` завершился ошибкой;
- `WorkerTerminatedError extends Error` — Worker аварийно или принудительно завершён;
- `JobRunnerClosedError extends Error` — запуск начат после начала закрытия.

Фреймворк самостоятельно не завершает основной процесс.

## Вне scope

- Создание экземпляров HTTP-контроллеров и выполнение HTTP-обработчиков.
- Публичный доступ к `JobRunner` или `WorkerPool`.
- Внедрение пользовательского пула или исполнителя в `Application`.
- Приоритеты, автоматические retry и гарантия exactly-once.
- Несколько одновременно выполняющихся задач в одном Worker.
- Transferable-объекты и `transferList`.
- Удалённые, `data:` и другие не-`file:` URL модулей.
- Hot reload и очистка ESM module cache.
- Распределённые очереди и выполнение задач вне текущего процесса Node.js.
