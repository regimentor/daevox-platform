# Реализовать выполнение фоновых задач в пуле Worker

Реализовать согласованный контракт из [`../spec.md`](../spec.md) в `lib/framework/` с использованием `node:worker_threads`.

## Требования

- Создать публичный базовый `Job`, внутренние `JobRunner` и `WorkerPool`, а также Worker bootstrap.
- Добавить владение единственным исполнителем задач и конфигурацию `jobs` в `Application`.
- Добавить идемпотентный `Application.close()` с ограниченным graceful shutdown.
- Реализовать строгую проверку класса задачи в основном потоке и повторную проверку default-экспорта в Worker.
- Реализовать ленивый ограниченный пул, FIFO-очередь, backpressure, отмену, тайм-ауты, обработку аварий Worker и очистку ресурсов.
- Добавить согласованные классы ошибок в `lib/framework/errors.js`.
- Добавить unit- и integration-тесты на контракт задачи, передачу данных и ошибок между потоками, очередь, параллелизм, отмену, тайм-аут, аварийное завершение, закрытие и отсутствие утечек Worker.
- Использовать только JavaScript в файлах `.js` и встроенные возможности Node.js; runtime-зависимости не добавлять.
- Добиться успешного выполнения `npm run check`.

## Критерии приёмки

- Поведение соответствует всем разделам `spec.md`.
- `JobRunner` и `WorkerPool` не раскрыты через публичные свойства `Application`.
- Некорректный класс или options отклоняются до изменения состояния очереди.
- Одновременно выполняется не больше `poolSize` задач, а ожидающая очередь не превышает `queueSize`.
- Каждая принятая задача завершает свой Promise ровно один раз при успехе, ошибке, отмене, тайм-ауте или аварии Worker.
- После `await application.close()` процесс не удерживается Worker-потоками и новые задачи не принимаются.
- Создание контроллеров и HTTP execution pipeline не реализуются в рамках задачи.
