# Зафиксировать архитектуру middleware

Превратить draft [`../spec.md`](../spec.md) в принятое архитектурное решение до изменения
production-кода.

## Требования

- Прочитать `CONTEXT.md`, `README.md` и связанные ADR 0002, 0003, 0005 и 0008.
- Добавить новый ADR, фиксирующий единый контракт `(ctx, next)`, три уровня middleware и
  транспортно-специализированную регистрацию на уровне приложения.
- Зафиксировать, что WebSocket middleware обрабатывают сообщения протокола, а `onConnect` и
  `onDisconnect` остаются одиночными глобальными lifecycle callbacks без `connectionMiddleware`.
- Зафиксировать request-scoped `state` для HTTP и session-scoped `state` для WebSocket.
- Зафиксировать error modes `MiddlewareExecutionError`, `WebSocketEventError` и использование
  `HttpError` для ожидаемого отказа WebSocket handshake.
- Явно описать пересмотр тех частей ADR 0008, которые затрагиваются прикладными кодами ошибок и
  аутентификацией в `onConnect`; server push и объединение пользовательских сессий оставить вне
  решения.
- Добавить в `CONTEXT.md` согласованные термины middleware, не смешивая HTTP-запрос и сообщение
  WebSocket-протокола.
- После принятия ADR заменить `Status: draft` в спецификации на ссылку на новый ADR и актуальный
  статус.

## Критерии приёмки

- Новый ADR не конфликтует с действующими ADR либо явно заменяет конфликтующие положения.
- В ADR однозначно определены уровни, порядок, short-circuit, состояние контекста и ошибки.
- `CONTEXT.md` содержит термины, достаточные для последующей двуязычной документации кода.
- Server push, индекс субъектов и распределённое хранение сессий не попадают в scope middleware.
- Markdown проходит существующие проверки репозитория.
