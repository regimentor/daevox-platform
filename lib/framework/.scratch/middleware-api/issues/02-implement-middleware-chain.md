# Реализовать общий исполнитель middleware-цепочки

Реализовать внутренний глубокий модуль композиции middleware и общие публичные ошибки согласно
[`../spec.md`](../spec.md), не подключая его пока к HTTP- или WebSocket-transport.

## Требования

- Работать через TDD и писать исходный код и тесты только в `.js`.
- Реализовать внутреннюю композицию упорядоченного массива middleware и terminal handler.
- Поддержать синхронные функции, Promise, действия до и после `await next()` и short-circuit.
- Гарантировать не более одного вызова конкретного `next()` и создавать публичный
  `MiddlewareExecutionError` при нарушении.
- Возвращать окончательный результат цепочки без транспортной нормализации.
- Не перехватывать ошибку внутри общего модуля окончательно: transport должен получить её и
  применить собственный error mode.
- Добавить публичный `WebSocketEventError` с проверкой прикладного кода и запретом зарезервированных
  кодов протокола.
- Экспортировать новые ошибки тем же способом, что и существующие публичные ошибки фреймворка.
- Добавить двуязычный JSDoc с `@public`/`@private` для всего нового production-кода.

## Критерии приёмки

- Unit-тесты доказывают точный прямой и обратный порядок цепочки.
- Покрыты short-circuit, замена результата, мутация и возврат исходного результата.
- Покрыты синхронный `throw`, rejected Promise, ошибка после `await next()` и повторный `next()`.
- `MiddlewareExecutionError` и `WebSocketEventError` доступны через публичные импорты и
  поддерживают `instanceof`.
- Некорректные и зарезервированные коды `WebSocketEventError` отклоняются синхронно.
- `npm run docs:build` и релевантные unit-тесты завершаются успешно.
