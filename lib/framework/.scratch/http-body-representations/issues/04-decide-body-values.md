# Зафиксировать значения представлений тела HTTP-запроса

## Question

Какие точные значения и гарантии возвращают JSON-, text-, bytes- и form-операции: тип JSON,
копирование bytes, повторяющиеся поля формы, имена и MIME-типы файлов, пустые тела и владение
полученными объектами?

## Answer

`json()` возвращает любое значение, допустимое для `JSON.parse`: object, array, string, number,
boolean или `null`. `JsonBody` из `HttpRequestContext<JsonBody, State>` является только статической
аннотацией результата и не выполняет runtime-валидацию прикладной схемы.

`text()` возвращает строку, а `bytes()` — новый независимый Node.js `Buffer`. Пользователь может
изменять этот `Buffer`, не затрагивая внутренний snapshot тела HTTP-запроса. Точные charset-правила
для `text()` определяются отдельно.

`formData()` возвращает нативный `FormData`. URL-encoded и текстовые multipart-поля представлены
строками; multipart-файлы — нативными in-memory `File`; повторяющиеся имена и исходный порядок
сохраняются стандартной семантикой `FormData`, включая `getAll()`. Полученные `FormData`, `File` и
`Buffer` остаются пригодными после завершения HTTP-обработчика, пока пользовательский код хранит
ссылки; framework не инвалидирует их и не владеет временными файлами.

Для `File` контракт гарантирует стандартные `name`, `type` и `size`, но не `lastModified`.
`File.name` является недоверенными multipart-данными: framework сохраняет стандартное значение
parser, не превращает его в filesystem-safe имя и документирует запрет использовать его как путь
без прикладной нормализации.

При корректном для выбранной операции `Content-Type` пустое тело даёт пустой `Buffer` для
`bytes()`, пустую строку для `text()`, ошибку разбора для `json()` и пустой `FormData` для
URL-encoded формы. Пустой multipart без корректной завершающей boundary является malformed input.
Правила отсутствующего или неподходящего `Content-Type` и точные классы ошибок остаются следующим
decision tickets.
