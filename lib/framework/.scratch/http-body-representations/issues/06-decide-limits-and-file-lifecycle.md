# Определить лимиты и жизненный цикл файлов

## Question

Какие aggregate-, field-, file- и part-лимиты действуют при ограниченном буферизованном чтении,
как они конфигурируются и измеряются, где живут bytes загруженных файлов, и какие гарантии очистки,
отмены и shutdown обязательны до появления streaming?

## Answer

Первая версия использует один aggregate `bodyLimit` для фактически полученных wire bytes всего
тела независимо от выбранной операции. Отдельные лимиты `field`, `file`, `parts` и `files` не
обещаются. Глобальный `http.bodyLimit` сохраняет default `1_048_576` bytes (`1MiB`), а декларация
HTTP-маршрута получает необязательный `bodyLimit`, который переопределяет глобальное значение
только для этого HTTP-маршрута. Route override проверяется атомарно при регистрации и сохраняется в
замороженном metadata snapshot; `0` разрешает только пустое тело.

Оба уровня принимают числовое количество bytes либо человекочитаемую строку. Число должно быть
неотрицательным целым. Строка после удаления внешних пробелов должна содержать целое
неотрицательное число и обязательную регистронезависимую единицу; дроби, экспоненты, внутренние
пробелы, отрицательные и небезопасно большие результаты отклоняются при конфигурации. Значение сразу
нормализуется в целое число bytes, исходная строка не хранится.

Формула единиц:

- `B = 1` byte;
- `KB = 1_000`, `MB = 1_000_000`, `GB = 1_000_000_000` bytes;
- `KiB = 1_024`, `MiB = 1_048_576`, `GiB = 1_073_741_824` bytes.

Transport может заранее вернуть `413`, если корректный `Content-Length` превышает effective limit,
но всегда считает фактически полученные chunks и не доверяет отсутствующему, меньшему или ложному
значению заголовка. Chunked body прекращается сразу после пересечения лимита. Framework не выполняет
content decompression; лимит относится к bytes тела на wire и не включает заголовки.

После успешного или неуспешного завершения первой операции reader удаляет ссылку на внутренний
snapshot. `bytes()` перед этим создаёт независимый `Buffer`; результаты JSON/text/form от snapshot
не зависят. При отмене клиента или принудительном HTTP shutdown незавершённое чтение прекращается,
внутренние chunks и snapshot освобождаются, а ожидающая операция отклоняется. Уже возвращённые
значения не инвалидируются.

Временные файлы не создаются: нативные `File` полностью живут в памяти. Возвращённые `Buffer`,
`FormData` и `File` остаются валидными, пока пользователь хранит ссылки, и освобождаются сборщиком
мусора. `bodyLimit` не является heap-limit: внутренний snapshot, копии `Buffer`/`File`, parser
overhead и параллельные запросы могут заметно увеличить пиковую память; это является обязательным
предупреждением публичной документации.

Точный public TypeScript-тип size-строк, классы ошибок отмены и момент сетевого чтения определяются
последующими decision tickets.
