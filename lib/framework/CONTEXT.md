# Транспортный фреймворк Daevox

Контекст фиксирует единый язык HTTP-фреймворка и различия между его основными понятиями.

## Язык

**Приложение (`Application`)**:
Общая точка композиции транспортных возможностей, предоставляемых фреймворком.
_Избегать_: HTTP-приложение, сервер, контейнер.

**HTTP-контроллер (`HttpController`)**:
Группа связанных HTTP-возможностей, опубликованных под общим префиксом.
_Избегать_: контроллер, сервис, endpoint.

**HTTP-маршрут (`HttpRoute`)**:
Соответствие HTTP-метода и пути обработчику контроллера.
_Избегать_: маршрут, endpoint, URL.

**HTTP-обработчик (`HttpHandler`)**:
Операция HTTP-контроллера, на которую указывает HTTP-маршрут.
_Избегать_: обработчик, action, callback.

**HTTP-маршрутизатор (`HttpRouter`)**:
Каталог HTTP-маршрутов приложения, используемый для сопоставления HTTP-запроса с HTTP-маршрутом.
_Избегать_: маршрутизатор, dispatcher.

**Контекст HTTP-запроса (`HttpRequestContext`)**:
Нормализованное представление данных одного HTTP-запроса и сигнала его отмены, доступное HTTP-обработчику без транспортных объектов Node.js.
_Избегать_: контекст запроса, request, payload.

**HTTP-ответ (`HttpResponse`)**:
Явно заданный HTTP-обработчиком статус, заголовки и тело результата обработки HTTP-запроса.
_Избегать_: ответ, result, response object.

**HTTP middleware (`HttpMiddleware`)**:
Функция `(ctx, next)`, окружающая выполнение найденного HTTP-обработчика на уровне приложения,
HTTP-контроллера или HTTP-маршрута.
_Избегать_: hook, interceptor, middleware запроса.

**Состояние HTTP-запроса (`HttpRequestState`)**:
Изменяемый объект `ctx.state` с временем жизни одного успешно маршрутизированного HTTP-запроса.
_Избегать_: глобальное состояние, состояние приложения, session state.

**Состояние приложения (`AppState`)**:
Единственный прикладной объект, созданный `Application` из переданного класса и общий для
HTTP-обработчиков, WebSocket-обработчиков и их middleware в течение жизни приложения.
_Избегать_: singleton, состояние HTTP-запроса, состояние WebSocket-сессии.

**WebSocket-контроллер (`WebSocketController`)**:
Именованная группа связанных WebSocket-событий протокола.
_Избегать_: контроллер, socket handler, channel, endpoint.

**WebSocket-событие (`WebSocketEvent`)**:
Именованный вид сообщения протокола, принадлежащий одному WebSocket-контроллеру.
_Избегать_: сообщение, route, action.

**Сообщение WebSocket-протокола (`WebSocketProtocolMessage`)**:
Сообщение между клиентом и приложением, адресованное парой WebSocket-контроллера и WebSocket-события и содержащее JSON-совместимый объект тела.
_Избегать_: WebSocket frame, payload, request, response.

**WebSocket-сессия (`WebSocketSession`)**:
Одно WebSocket-соединение клиента, имеющее уникальный `sessionId` и существующее до закрытия соединения.
_Избегать_: клиент, вкладка, socket.

**WebSocket-клиент (`WebSocketClient`)**:
Созданная фреймворком техническая сторона одной или нескольких WebSocket-сессий, объединённых
стабильным `clientId` на время их активности.
_Избегать_: пользователь, аккаунт, несколько соединений.

**Хранилище WebSocket-сессий (`WebSocketSessionStore`)**:
Внутренний каталог WebSocket-сессий и индекс `clientId → Set<sessionId>` активных сессий.
_Избегать_: controller state, client registry.

**WebSocket sender (`WebSocketSender`)**:
Узкий application-wide фасад, через который HTTP-контроллер отправляет envelope `daevox.v1` в
активные WebSocket-сессии по `clientId` и, при необходимости, выбранным `sessionIds`.
_Избегать_: raw socket, session store, push channel.

**Middleware сообщения WebSocket (`WebSocketMessageMiddleware`)**:
Функция `(ctx, next)`, окружающая выполнение обработчика успешно маршрутизированного
WebSocket-события на уровне приложения, WebSocket-контроллера или WebSocket-события.
_Избегать_: connection middleware, WebSocket hook, middleware сессии.

**Состояние WebSocket-сессии (`WebSocketSessionState`)**:
Изменяемый объект `ctx.state`, общая ссылка на который живёт от `onConnect` до `onDisconnect` одной
WebSocket-сессии и доступна обработчикам её сообщений.
_Избегать_: состояние WebSocket-сообщения, глобальное состояние, user state.

**Слушатель событий (`EventListener`)**:
Именованный долгоживущий получатель внутренних событий приложения, обрабатывающий
адресованные ему события по одному в порядке их приёма без подписок и fan-out.
_Избегать_: subscriber, WebSocket-контроллер, pub/sub consumer.

**Внутреннее событие (`ApplicationEvent`)**:
Именованный вид fire-and-forget сообщения приложения, адресованного парой слушателя
событий и имени события; исход его обработки не входит в операцию отправителя.
_Избегать_: WebSocket-событие, pub/sub event, domain event.

**Адрес внутреннего события (`ApplicationEventAddress`)**:
Пара имени слушателя событий и имени внутреннего события, однозначно выбирающая один
обработчик.
_Избегать_: controller/event, topic, subscription key.

**Event sender (`EventSender`)**:
Узкий фасад, через который HTTP- или WebSocket-контроллер передаёт адресованное внутреннее
событие для независимой обработки слушателем событий.
_Избегать_: event bus, publisher, pub/sub producer.

**Цепочка middleware (`MiddlewareChain`)**:
Упорядоченное выполнение middleware приложения, контроллера и декларации обработчика вокруг
HTTP-обработчика или обработчика WebSocket-события.
_Избегать_: pipeline, lifecycle, middleware stack.

**Исполнитель задач (`Job Runner`)**:
Внутренний компонент приложения, принимающий классы задач и передающий их на выполнение в пул работников.
_Избегать_: handler runner, controller worker.

**Задача (`Job`)**:
Работа, описанная пользователем как класс с контрактом выполнения и выполняемая независимо от обработки HTTP-маршрута.
_Избегать_: request, handler.

**Пул работников (`Worker Pool`)**:
Среда изолированного выполнения задач, управляющая работниками и распределением работы между ними.
_Избегать_: worker manager, job runner.
