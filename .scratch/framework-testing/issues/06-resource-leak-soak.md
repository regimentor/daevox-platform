# Добавить soak-тест утечек и долговременной деградации

Создать длительный периодический тест, обнаруживающий рост памяти, listeners, timers, соединений и Worker при повторяющихся HTTP, WebSocket и job lifecycle.

## Требования

- Реализовать настраиваемый короткий локальный режим и длительный scheduled-режим продолжительностью в несколько часов.
- Поддерживать устойчивую смешанную нагрузку из HTTP-запросов, WebSocket connect/message/disconnect и успешных, отменённых и завершившихся по timeout задач.
- Периодически создавать и закрывать WebSocket-сессии, чтобы проверять очистку session store и lifecycle hooks.
- Снимать временные ряды RSS, heap used, event-loop lag, active handles, соединений, Worker, throughput и latency.
- Отделить разогрев и допустимые ступенчатые изменения heap от устойчивого монотонного роста.
- Определить документированные пороги наклона памяти и деградации p95/p99 для однородного CI-окружения.
- При превышении порога сохранять сырые измерения и диагностические артефакты, достаточные для отдельного расследования.
- После нагрузки вызвать `Application.close()` и проверить возвращение счётчиков ресурсов к ожидаемому состоянию.

## Критерии приёмки

- Короткий режим проверяет сам harness и может быть воспроизведён локально.
- Scheduled-режим выдаёт машинно-читаемый временной ряд и итог по каждому порогу.
- Искусственно удерживаемый listener, timer или socket обнаруживается контрольной проверкой harness.
- После штатного прогона не остаются Worker, listener и клиентские соединения.
- Тест не входит в обычный `npm run check`, имеет timeout и отдельную npm-команду.

## Comments

Реализовано через TDD на публичных HTTP, WebSocket, Job и `Application.close()` seam’ах.
Добавлены отдельные команды `npm run soak:short`, `npm run soak:scheduled` и
`npm run test:soak-harness`; soak не входит в обычный `npm run check`. Mixed workload
непрерывно чередует HTTP, полные WebSocket lifecycle и успешные, отменённые и завершившиеся
по timeout задачи. Четырёхчасовой scheduled-профиль имеет общий timeout четыре часа пять
минут и 15-минутный warm-up.

Машинно-читаемый artifact содержит периодические RSS, heap used, event-loop lag, active
handles/resources, listener, timer, соединения, Worker, throughput и latency p50/p95/p99.
Анализ отделяет единичную ступень heap от устойчивого роста по наклону и доле растущих
интервалов, проверяет документированные пороги RSS/heap и деградации p95/p99, а после
`Application.close()` сверяет возврат ресурсов к baseline. Итоговые latency хранятся в
ограниченном histogram, а интервальные окна очищаются, поэтому сам четырёхчасовой harness не
накапливает массив измерений операций. При провале сохраняется отдельный diagnostics JSON.

Короткий штатный профиль и отрицательные контроли удержанных listener, timer и socket
проходят; все контроли завершаются ожидаемым кодом `1` и указывают превышенный счётчик.
`npm run check` проходит: 127 тестов и четыре smoke benchmark-профиля. Полный четырёхчасовой
scheduled-прогон оставлен для выделенного однородного CI-окружения.
