## Question

Согласовать место UI, команды, snapshot и события прогресса, выдачу медиа, синхронизацию плеера, seek/скорость, отображение текста/спикеров, ошибки и возвращение на страницу. ## Answer

Контракт согласован в двух раундах 2026-09-10. Скорость просмотра фиксирована на 1×; управление скоростью исключено пользователем. Реализация в рамках этой задачи не выполнялась.

### Пользовательский интерфейс

- Отдельная вкладка «Перевод видео» сохраняет вкладку «Транскрибация». Страница раздела содержит запуск по ссылке/файлу, текущую операцию и библиотеку; каждая запись открывается по прямой ссылке.
- На широком экране плеер слева и текст справа, на узком — текст под плеером. Реплика содержит спикера, время, оригинал и перевод; поддерживаются подсветка, переход по нажатию и отключаемая автопрокрутка.
- Текст появляется по мере подготовки, этапы показывают измеримый прогресс без фиктивного общего процента. Подтверждение голосов предшествует полной озвучке; просмотр с переводом доступен после подготовки результата.
- Плеер предоставляет паузу, перемотку, полный экран, раздельную громкость, «Только оригинал» и список проблемных моментов. Подготовительная коррекция отдельных реплик до 1,15× сохраняется отдельно от фиксированной скорости просмотра.

### Адреса и совместимость

- UI: /voiceover — запуск, текущая операция, библиотека; /voiceover/:id — страница записи.
- Новый API: /trancription-api/voiceovers. Существующие /trancription-api/operations и сценарий транскрибации сохраняют свой контракт, включая сохранение частичного текста при отмене. Точное написание существующего proxy-префикса сохраняется.
- Общий слот учитывает выполнение, ожидание подтверждения голосов и незавершённую очистку активной операции. Ошибка busy содержит вид и идентификатор активной операции для ссылки на неё.

### Команды

| Метод и путь относительно /trancription-api | Назначение |
| --- | --- |
| GET /activity | Общая активная операция: kind=transcription/voiceover, id, status или null. Не подменяет текущую операцию старого API. |
| GET /voiceovers | Библиотека: страницы по cursor, новые записи сначала; краткие статусы, название, длительность, размер и время создания. Без полного текста и локальных путей. |
| POST /voiceovers | Резервирование по YouTube-ссылке или метаданным файла и client_request_id. 201 для новой записи; 409 при занятости. |
| PUT /voiceovers/{id}/source | Потоковая загрузка файла после резервирования. После полной загрузки начинается подготовка. |
| GET /voiceovers/{id} | Текущее состояние, прогресс, реплики, голоса, проблемы и ссылки на доступные медиа. |
| GET /voiceovers/{id}/events | SSE: snapshot, progress, transcript, translation, state, deleted. |
| PUT /voiceovers/{id}/voices | Сохранение полного назначения голосов с expected_revision; только в awaiting_voices. |
| POST /voiceovers/{id}/synthesize | Подтверждение назначения и запуск озвучки с client_request_id и expected_revision. |
| DELETE /voiceovers/{id} | Для активной записи — отмена и полное удаление; для завершённой — удаление записи и файлов. 202 при выполняющейся очистке, 204 при завершённом удалении. Повтор не создаёт работу заново. |
| GET, HEAD /voiceovers/{id}/media/{asset_id} | Выдача опубликованного медиа, включая byte ranges для перемотки; идентификаторы вместо клиентских файловых путей. |
| GET, HEAD /voiceover-voices/{voice_id}/sample | Короткий опубликованный образец выбранного варианта Silero. |

- Повтор создания с тем же ключом и тем же содержимым возвращает ту же запись; другое содержимое с тем же ключом — 409. После удаления старый ключ отвечает 410 вместо повторного создания: сохраняется только служебная квитанция ключа без видео, текстов и назначения голосов.
- Повтор synthesize не запускает второй синтез. Несовпадение expected_revision — 409 с актуальным состоянием. Пользовательский повтор всей обработки получает новый ключ и новую запись.
- Если загрузка файла оборвалась, состояние становится failed с понятной ошибкой; возобновление upload не предусматривается. Гарантия продолжения обработки при закрытии вкладки начинается после завершённой передачи файла серверу.

### Состояние и события

- Статусы: awaiting_upload, preparing, awaiting_voices, synthesizing, completed, incomplete, failed, deleting, delete_failed. После успешного удаления запись отсутствует.
- Snapshot: id, revision, source, created_at, status, stages, speakers, voice_assignments, transcript, translations, problems, assets, storage_bytes, error. Для связи переводов с оригиналом использовать source_segment_ids; оригинальные временные границы не заменять временем озвучки.
- Transcript содержит id, start/end, text, speaker_id и overlap. Translation содержит id, source_segment_ids, text и статус подготовки. Готовая озвучка связывает перевод с фактическим playback_start/end; проблемный фрагмент имеет reason и исходный временной интервал.
- Этапы подготовки: получение видео, подготовка аудио, распознавание/спикеры, перевод, подготовка образцов. Затем awaiting_voices и синтез с подготовкой дорожки. Образцы готовятся по необходимости после действий пользователя; запуск API модели не загружает. Процесс подготовки образцов завершается до ожидания выбора; синтез полного перевода запускает свой процесс после подтверждения.
- В текстовых обновлениях допустимы замены ранее показанных фрагментов по revision. Не делать append-only предположение о спикерах или переводе. Оригинал/перевод во время подготовки — текстовый предпросмотр; готовая озвучка недоступна до completed/incomplete.
- SSE использует монотонные revisions и bounded replay. При пропуске истории — полный snapshot. Потеря SSE показывает потерю связи, не провал операции; повторное подключение сверяет состояние. При удалении — событие deleted; пропущенное событие компенсируется отсутствием записи при GET.

### Плеер

- Видео и подготовленная дорожка перевода раздельны, чтобы независимо регулировать громкость. Дорожка перевода имеет общую временную шкалу с видео и тишину вне размещённых реплик. Оригинальная дорожка остаётся в видео; клиент приглушает её в интервалах успешной озвучки.
- Видео — источник времени. Play/pause управляют обоими потоками. После перемотки или буферизации воспроизведение ожидает готовности обоих; перевод не играет отдельно от остановленного видео. Расхождение времени корректируется перемещением аудио к времени видео, без изменения скорости видео. Численный допуск синхронизации определить при приёмке.
- Просмотр только на скорости 1×. «Только оригинал» выключает перевод и приглушение оригинала. Обычный уровень оригинала определяется его регулятором; автоматическое приглушение применяется поверх этого уровня.
- Текст подсвечивается по исходным временным интервалам, включая все активные реплики при overlap. Проблемные моменты доступны отдельным списком; нажатие переходит к исходному интервалу. Полный экран включает оболочку плеера с его управлением.

### Ошибки и удаление

- Общая ошибка показывает причину и доступные результаты, предлагает новый запуск с начала или удаление. Ошибки отдельных реплик дают incomplete с проблемными интервалами, согласно ранее принятому решению.
- Удаление отображается как выполняющееся, пока процессы не завершены и принадлежащие записи файлы не удалены. При ошибке очистки — delete_failed и повтор удаления; не сообщать об успехе заранее. Если удаляется активная операция, её слот удерживается до успешной очистки.
- Удаление результата останавливает его открытый плеер. Клиент, пропустивший событие, обрабатывает отсутствие записи/медиа. Оригинальные пользовательские файлы вне хранилища и общие веса/образцы голосов удалению с записью не принадлежат.

### Конфигурация и проверка

- Уточнения единиц синтеза, групп overlap, отображения прерванных операций и допустимых источников согласованы в [Спецификации и критериях готовности перевода с озвучкой](07-acceptance.md#согласованные-уточнения). Статус прерванной обработки представлять через failed с причиной interrupted; незавершённое удаление — через delete_failed. Эти отображения конкретизируют согласованные статусы без добавления автоматического продолжения.
- Endpoint и идентификатор существующей LLM, параметры доступа и GPU TTS задаются на сервере. Секреты и абсолютные локальные пути не входят в браузерный контракт. Выбор новой LLM не производится.
- Приёмка должна проверить Silero с общим окружением, плеер с отдельной дорожкой, общую занятость, сетевые повторы и сбои очистки. Продолжение прерванной обработки после перезапуска остаётся вне scope.
