# Локальные модели перевода и русской многоголосой озвучки

Дата исследования: 2026-09-10. Контекст: личный локальный Daevox; английский → русский; предварительная обработка; разные синтетические голоса. Это исследование кандидатов, не выбор моделей и не измерение качества. Веса не скачивались, зависимости не устанавливались, inference не запускался.

## Вывод для следующего решения

Для первого сравнения предлагается **Qwen3-8B через llama-server для контекстного перевода** и **Silero v5_5_ru против Qwen3-TTS-12Hz-1.7B-CustomVoice для озвучки**. TranslateGemma 4B/12B полезна как специализированный переводческий конкурент; OPUS-MT — как лёгкая контрольная линия. Рекомендация опирается на интерфейсы и интеграционные ограничения, а не на доказанное превосходство качества.

Главное найденное препятствие интеграции: актуальный upstream qwen-tts требует Transformers 4.57.3 с huggingface-hub<1, тогда как GPU extra текущего transcription-backend требует huggingface-hub>=1. Разделение Python-окружений следует обсудить до выбора устройства сервиса.

## Текущее окружение проекта

В [pyproject транскрибации](../../../apps/transcription-backend/pyproject.toml) указаны Python >=3.12,<3.13, PyTorch/torchaudio 2.11.0, CTranslate2 4.8.2, huggingface-hub>=1.0,<2. Это ограничения текущего рабочего дерева, не подтверждение установленных версий. Lock и разрешение новой совокупности зависимостей не проверялись. [Summarizer](../../../apps/backend/src/domain/secretary/summarizer.ts) и [auto-reply](../../../apps/backend/src/domain/auto-reply/content.ts) используют LLAMA_BASE_URL/LLAMA_MODEL; доступность сервера и фактически загруженная модель не проверялись.

Прежняя [карта транскрибации](../../local-transcription/map.md) сообщает RTX 5080/4070 Ti и отсутствие доступных CUDA-устройств в окружении агента. Это не обещание свободной VRAM. По NVIDIA их compute capability — 12.0 и 8.9 соответственно. [Таблица GPU](https://developer.nvidia.com/cuda/gpus).

Уточнение TranslateGemma: открытая карточка не перечисляет все языки; сотрудник Google отсылает к chat_template.jinja. Получение официального файла в этой сессии вернуло 401. Поэтому допустимость `en`/`ru` в выбранной закреплённой версии шаблона следует проверить при подготовке весов; не выдаём сторонний список языков за проверку артефакта. [Ответ Google](https://huggingface.co/google/translategemma-27b-it/discussions/1).

llama-server поддерживает локальный HTTP chat endpoint, schema-constrained JSON и передачу `enable_thinking` шаблону. Это позволяет отделить транспорт модели от прикладного перевода, но схема JSON не гарантирует отсутствие пропусков смысла. Интеграционный тест нужен для конкретной версии сервера и GGUF. Поддержка TranslateGemma именно в текущем сервере не подтверждена. [Документация сервера](https://github.com/ggml-org/llama.cpp/tree/master/tools/server).

## Длительность и контекст

Silero поддерживает SSML-паузы и несколько уровней темпа; это не API «сгенерировать ровно N миллисекунд». [SSML](https://github.com/snakers4/silero-models/wiki/SSML). Qwen допускает текстовые инструкции о темпе; в просмотренном штатном API CustomVoice не найден обязательный точный target-duration. Следовательно, синхронизацию нельзя считать решённой выбором TTS.

Предлагаемый предмет следующего решения: переводить смысловыми группами с сохранением ссылок на исходные сегменты; хранить перевод для чтения и фактически озвучиваемую редакцию; измерять получившийся WAV; перерабатывать только слишком длинные фразы; согласовать предел ускорения и использование пауз. Нельзя обрезать аудио по таймеру или сокращать факты без явной политики. Соответствие реплик, имён, чисел, отрицаний и терминов проверяется отдельно от синтаксиса ответа модели.

## Python, GPU и оценка ресурсов

**Подтверждённый конфликт metadata:** upstream [qwen-tts pyproject](https://github.com/QwenLM/Qwen3-TTS/blob/main/pyproject.toml) закрепляет transformers==4.57.3 и accelerate==1.12.0. [Transformers 4.57.3 setup.py](https://github.com/huggingface/transformers/blob/v4.57.3/setup.py) требует huggingface-hub>=0.34.0,<1.0; это несовместимо с >=1.0,<2 текущего transcription-backend GPU extra. Это сравнение деклараций, а не запуск resolver или доказательство невозможности всех будущих комбинаций. Рекомендация: отдельное uv-окружение TTS и процесс с небольшим контрактом; совместимость Python 3.12 сама по себе недостаточна. Приложение при этом может оставаться одним сервисом.

Авторы Qwen рекомендуют отдельное Python 3.12 окружение и FlashAttention 2. FA2 документирует Ampere/Ada/Hopper, тогда как отдельный FA4 описывает Hopper/Blackwell. Поэтому пример с `flash_attention_2` нельзя автоматически объявить рабочим на RTX 5080; выбор attention backend и wheel следует проверить для sm_120. На 4070 Ti архитектура Ada соответствует списку FA2, но это ещё не проверка всей среды. [FlashAttention](https://github.com/Dao-AILab/flash-attention).

Грубая арифметика веса, **не оценка пика VRAM**: 8B×0.5 байта ≈4 GB при условных 4 битах; 12B×0.5 ≈6 GB; 4B×2 ≈8 GB BF16; 1.7B×2 ≈3.4 GB; 0.6B×2 ≈1.2 GB. Реальные форматы добавляют метаданные/неквантованные тензоры; нужны KV cache, активации, аудиокодек, буферы, CUDA context. Точный размер скачивания и пик не установлены. Две GPU не образуют автоматически общий пул памяти; нельзя обещать одновременную загрузку ASR, диаризации, LLM и TTS. CPU Silero стоит измерить как явно выбранный режим освобождения GPU.

## Что измерить до окончательного выбора

1. Доступ к обеим GPU из реального процесса сервиса, свободная VRAM, точные версии драйвера/CUDA/wheels; отдельно import/inference каждого кандидата.
2. На одинаковых 20–30 отрывках: пропуски/добавления, числа, отрицания, терминология, ссылки между репликами; слепое сравнение переводов. Результаты общих бенчмарков не заменяют проверку YouTube-речи.
3. Русская речь всех рассматриваемых пресетов: ударения, акцент, аббревиатуры, английские имена, смешанный текст, стабильность одного голоса на удалённых репликах.
4. Cold start, пик VRAM/RAM, реальное время на минуту аудио, короткие/длинные фразы, batch=1 и малые batches; повтор после отмены и освобождение памяти.
5. Доля фраз, не помещающихся в интервал, и качество после допустимой коррекции; число неудачных повторов. Порог качества и допустимое ожидание согласуются с пользователем.
6. Повтор с полностью подготовленным локальным кэшем без сети; версии весов, tokenizer, голосов и параметров сохраняются в артефакте результата.

Ни один из этих пунктов пока не выполнен. Разрешено исследование фактов; выбор моделей, приемлемый акцент, длительность ожидания и политика синхронизации остаются HITL-решениями карты.
