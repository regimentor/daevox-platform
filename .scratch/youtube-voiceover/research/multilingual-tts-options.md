# Многоязычная локальная TTS для русского перевода с английскими терминами

Дата проверки: 2026-09-11. Цель — проверить альтернативы Silero, не менять production и не запускать backend. Проверка документации отделена от аудиоэксперимента. Наличие русского и английского в списке языков само по себе не доказывает переключение языка внутри предложения.

## Кандидаты и подтверждённые ограничения

**Qwen3-TTS CustomVoice 0.6B / 1.7B.** Обе версии поддерживают русский и английский среди десяти языков и девять фиксированных голосов. Нативного русского пресета нет; Ryan и Aiden — английские. Авторы рекомендуют родной язык голоса для лучшего качества. Управление стилем инструкциями заявлено для 1.7B; для 0.6B в таблице возможностей оно отсутствует. `language='Auto'` означает автоматическую адаптацию языка, а не опубликованную гарантию корректного произношения RU+EN. Лицензия Apache-2.0. [Официальный репозиторий](https://github.com/QwenLM/Qwen3-TTS), [карточка весов](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice).

У обёртки `generate_custom_voice` есть текст, язык, speaker и параметры генерации; возвращаются массивы аудио и sample rate. Максимум новых codec tokens по умолчанию 2048 — это ограничитель генерации, не гарантированная длина аудио. Слишком низкий предел может обрезать фразу. Публичного параметра «сказать ровно за N секунд» в проверенном API нет. [Код обёртки](https://github.com/QwenLM/Qwen3-TTS/blob/main/qwen_tts/inference/qwen3_tts_model.py).

**Chatterbox Multilingual V3, 0.5B.** Русский и английский входят в 23 поддерживаемых языка; MIT. Нужна именно Multilingual, не English-only Turbo/Nano. Один голос можно задавать референсом; авторы предупреждают, что язык референса влияет на акцент. Это другой UX вместо пяти пресетов Silero: нужен каталог заранее подготовленных разрешённых голосов и образцов. В рассмотренной документации нет проверенного обещания RU+EN code-switching внутри реплики. [README](https://github.com/resemble-ai/chatterbox), [лицензия](https://github.com/resemble-ai/chatterbox/blob/master/LICENSE).

В актуальном исходном коде V3 включается явно `t3_model='v3'`; без этого параметра default остаётся V2. `generate(..., language_id='ru')` задаёт язык всей реплики. Поэтому это резервный эксперимент, не доказанное исправление смешанного текста. Загрузка V3 использует `t3_mtl23ls_v3.safetensors`, `s3gen.pt`, `ve.pt`, `conds.pt`, `grapheme_mtl_merged_expanded_v1.json`. [Исходный код Multilingual](https://github.com/resemble-ai/chatterbox/blob/master/src/chatterbox/mtl_tts.py).

## Размеры, кэш и окружения

Проверено реальным `hf download --dry-run` 2026-09-11. До эксперимента соответствующих Qwen-TTS/Chatterbox файлов не найдено в `~/.cache/huggingface` и `apps/transcription-backend/data`.

| Набор | Размер скачивания по HF | Состав |
| --- | --- | --- |
| Qwen 0.6B CustomVoice | 2.5 GB | 1.8 GB основной safetensors + 682.3 MB вложенный speech tokenizer и служебные файлы |
| Qwen 1.7B CustomVoice | 4.5 GB | 3.8 GB основной safetensors + тот же размер tokenizer |
| Chatterbox V3 необходимые файлы | 3.2 GB | 2.1 GB T3 + 1.1 GB S3Gen + небольшие файлы |

Это дисковые размеры, не пик VRAM. Полный CustomVoice snapshot уже содержит `speech_tokenizer/`: для этого API не требуется ещё одно скачивание отдельного tokenizer repo. Источники файлов: [Qwen 0.6B](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice/tree/main), [Qwen 1.7B](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice/tree/main), [Chatterbox](https://huggingface.co/ResembleAI/chatterbox/tree/main).

Qwen runtime `qwen-tts==0.1.1` закрепляет Transformers 4.57.3 и Accelerate 1.12.0. Требуется отдельная среда от transcription-backend с `huggingface-hub>=1`: зависимость Transformers 4.57.3 требует hub<1. Python 3.12 рекомендован авторами. Для RTX 5080 в эксперименте выбран штатный SDPA: модель объявляет `_supports_sdpa=True`; это позволяет не собирать FlashAttention 2. [Qwen metadata](https://github.com/QwenLM/Qwen3-TTS/blob/main/pyproject.toml), [Transformers metadata](https://github.com/huggingface/transformers/blob/v4.57.3/setup.py), [attention implementation](https://github.com/QwenLM/Qwen3-TTS/blob/main/qwen_tts/core/models/modeling_qwen3_tts.py).

Chatterbox upstream рекомендует протестированный Python 3.11. В текущем pyproject для Python<3.14 закреплены Torch/torchaudio 2.6.0 и Transformers 5.2.0; указан Perth из git master. Для воспроизводимости нужны отдельная среда, фиксированный commit самого проекта и Perth, проверка wheels под конкретную GPU. Нельзя ставить этот набор поверх рабочего backend либо Qwen. [Chatterbox metadata](https://github.com/resemble-ai/chatterbox/blob/master/pyproject.toml).

## Предлагаемая интеграция

Добавить внешний TTS worker с прежним файловым/JSON контрактом: вход `phrase_id`, `spoken_text`, `speaker_id`; выход WAV, фактическая длительность, диагностический статус. Выбор `tts_engine` относится ко всему результату, а не произвольно меняется между словами. Процесс запускается отдельным Python executable после освобождения ASR/диаризации; модель загружается один раз на пакет фраз и выгружается завершением процесса. Не требуется постоянно работающий второй HTTP backend.

Сохранять `display_text` с Rust/GPU/C++ отдельно от `spoken_text`, версии глоссария, движка, весов и голоса. Даже при Qwen глоссарий полезен для неоднозначного произношения аббревиатур. Сначала испытывать естественный смешанный текст; если конкретный термин плохо читается — применять выборочную подсказку произношения. Замена движка не должна удалять проверки полноты перевода и озвучки.

Не выбирать модель по наличию WAV: проверять по ожидаемым терминам и окончаниям фраз, слушать контрольные примеры, измерять скорость и память. ASR-проверка — дополнительный сигнал: она сама способна нормализовать или ошибаться на терминах. Не выдавать совпадение распознавания за доказательство естественного звучания.

## Реальный минимальный эксперимент Qwen

Подготовлен изолированный каталог `apps/transcription-backend/data/tts-options/`, Python3.12, `qwen-tts==0.1.1`, Torch/torchaudio2.11.0; production зависимости не меняются. Модель закреплена на `85e237c12c027371202489a0ec509ded67b5e4b5`.

`qwen-benchmark.py` проверяет одну и ту же реплику в `Russian` и `Auto` для Ryan, сначала с латиницей, затем с кириллическими произношениями:

> Компания AMD использует Rust для GPU, а не C++. WebGPU — это API, а runtime — среда выполнения.

> Компания эй эм ди использует раст для джи пи ю, а не си плюс плюс. Веб джи пи ю — это эй пи ай, а рантайм — среда выполнения.

Используются BF16, SDPA, фиксированный seed, batch=1; результат содержит WAV, время загрузки/синтеза, длительность, sample rate, RMS и пиковую память PyTorch. Эти четыре фрагмента проверяют осуществимость, но не заменяют сравнение всех голосов и длинного ролика. Статус реального запуска и измерения добавляются после завершения.

Уточнение доказательств качества: в техническом отчёте Qwen таблица 9 даёт русский WER 5.809 для 12Hz0.6B-CustomVoice и 4.734 для 12Hz1.7B-CustomVoice на авторском наборе/Aiden. Это полезный аргумент испытать 1.7B позже, но не оценка нашего ролика и не проверка английских вставок. Cross-lingual benchmark означает перенос голоса между языками, а long-form набор отчёта — китайский/английский; нельзя переносить эти результаты на длинный смешанный русский текст. [Первичный отчёт](https://arxiv.org/html/2601.15621v1).

### Измеренный результат 2026-09-11

Все четыре генерации завершились, процесс вышел с кодом 0. RTX 5080 использована отдельно через UUID; RTX 4070 Ti с пользовательским LLM не использовалась. Backend не запускался. `SoX` не найден и FlashAttention не установлен — предупреждения не помешали выбранному 12Hz/SDPA пути.

| Вход / language | Длина WAV | Синтез | Пик allocated PyTorch |
| --- | ---: | ---: | ---: |
| Смешанный / Russian | 11.04 с | 5.40 с | 2392 MiB |
| Кириллица / Russian | 25.36 с | 11.81 с | 2774 MiB |
| Смешанный / Auto | 13.76 с | 6.22 с | 2471 MiB |
| Кириллица / Auto | 11.44 с | 5.30 с | 2403 MiB |

Все WAV — 24 kHz. Наибольший `max_memory_reserved` — 3346 MiB; это allocator PyTorch, не полный пиковый расход устройства с CUDA context. Загрузка модели из уже скачанных/прогретых файлов заняла 0.76 с после импорта библиотек; нельзя выдавать это за полный cold-start. Параметры и точные замеры сохранены в `apps/transcription-backend/data/tts-options/qwen-output/result.json`; среда закреплена в `qwen-runtime-freeze.txt`.

Вариант «кириллица / Russian» оказался более чем вдвое длиннее других. Это повод проверить паузы/повторы/полноту, а не доказательство лучшей разборчивости. Прослушивание и диагностическое ASR ещё не включены в эти измерения. Успешная генерация означает техническую осуществимость на имеющемся GPU, но не доказанное устранение пропусков английских терминов.
