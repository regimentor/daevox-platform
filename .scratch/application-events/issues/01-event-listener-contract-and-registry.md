# Реализовать контракт EventListener и registry

## Question

Реализовать публичный `EventListenerBase`, строгую декларацию listener, конфигурацию `events`, публичные ошибки и внутренний
каталог адресов по [`../spec.md`](../spec.md).

## Требования

- Работать через TDD; исходники и тесты писать только в `.js`.
- Добавить абстрактный `EventListenerBase`, запрещающий прямое создание.
- Проверять прямое наследование, собственные `static name` и непустой `static events`.
- Проверять строгую декларацию `{ name, data, handler }`, wire-имена, DTO-класс и собственный prototype-метод.
- Отклонять лишние, symbol-, accessor- и унаследованные поля.
- Атомарно копировать и замораживать каталог; отклонять повтор класса, listener name и адреса.
- Добавить строгую нормализацию `events.queueSize`, `handlerTimeout`, `shutdownTimeout` и `onError` с согласованными defaults.
- Добавить восемь публичных классов ошибок и их публичные экспорты.
- Не экспортировать registry и будущие sender/mailbox как публичные классы.
- Добавить двуязычный JSDoc с `@public`/`@private` для production-кода.

## Критерии приёмки

- Unit-тесты покрывают все валидные и невалидные формы опций, класса и деклараций.
- Последующая мутация исходного `events` не меняет registry.
- Ошибки доступны из публичного entry point и поддерживают `instanceof`.
- Релевантные unit-тесты и `npm run docs:build` завершаются успешно.

## Comments

Архитектура и терминология согласованы в ADR 0011 и `CONTEXT.md`.
