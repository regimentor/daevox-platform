# Регистрация HTTP-контроллеров и маршрутизация

## Назначение

Добавить минимальную модель регистрации HTTP-контроллеров и сопоставления статических и динамических HTTP-маршрутов. Реализация располагается в `lib/framework/` и не включает HTTP-сервер, создание экземпляра контроллера или выполнение HTTP-обработчика.

## Компоненты

### `HttpControllerBase`

- Экспортируется именованным экспортом из `lib/framework/HttpControllerBase.js`.
- Не содержит прикладных методов или состояния.
- Не допускает прямого создания экземпляра.
- HTTP-контроллер обязан напрямую наследовать `HttpControllerBase`; промежуточные базовые классы не допускаются.

### `Application`

- Экспортируется именованным экспортом из `lib/framework/Application.js`.
- При создании сразу создаёт приватный экземпляр `HttpRouter`.
- Предоставляет `registerHttpController(HttpController)`.
- Принимает класс, а не экземпляр.
- Проверяет прямое наследование `HttpControllerBase`.
- Требует собственное непустое строковое статическое поле `prefix`.
- Требует собственное статическое поле `routes`, содержащее непустой массив.
- Требует, чтобы каждый указанный HTTP-обработчик был собственным методом-функцией `HttpController.prototype`. Статические и унаследованные методы не допускаются.
- Отклоняет повторную регистрацию того же класса.
- Полностью проверяет и нормализует метаданные до изменения состояния.
- Передаёт все определения одного контроллера в один атомарный вызов `HttpRouter.registerAll(routes)`.
- При успехе возвращает собственный экземпляр.
- Не предоставляет доступ к приватному `HttpRouter` и не предоставляет публичный метод сопоставления.

### `HttpRouter`

- Реализуется в `lib/framework/HttpRouter.js` как внутренний компонент, не входящий в пользовательский публичный API.
- Предоставляет `registerAll(routes)` и `match(method, pathname)`.
- `registerAll` валидирует всю пачку и все конфликты до изменения каталога.
- `registerAll` ничего не возвращает.
- Удаление маршрутов не поддерживается.

## Декларация контроллера

```js
class UsersController extends HttpControllerBase {
  static prefix = '/users';

  static routes = [
    { method: 'GET', path: '/', handler: 'list' },
    { method: 'GET', path: '/:id', handler: 'getById' },
  ];

  list() {}

  getById() {}
}
```

- Декларация HTTP-маршрута содержит ровно `method`, `path` и `handler`; неизвестные поля отклоняются.
- `method`, `path` и `handler` являются непустыми строками.
- HTTP-метод является любым корректным HTTP token и нормализуется в верхний регистр.
- Имя обработчика не ограничивается грамматикой идентификатора, но должно указывать на собственный метод-функцию.
- Дополнительные статические поля класса контроллера игнорируются.

## Нормализованное определение маршрута

```js
{
  method: 'GET',
  path: '/users/:id',
  handler: 'getById',
  controller: UsersController,
}
```

- `Application` создаёт новое определение, не связанное с объектом из `static routes`.
- Определение замораживается до помещения в каталог.
- Изменение статических метаданных после регистрации не изменяет каталог.

## Нормализация пути

- `prefix` и локальный `path` маршрута могут быть записаны без начального `/`.
- Пустые строки не допускаются; корень записывается как `/`.
- Канонический путь начинается с `/`, не содержит повторных `/` и не заканчивается `/`, кроме корня.
- Композиция путей даёт: `/` + `/` → `/`, `/users` + `/` → `/users`, `/` + `/ping` → `/ping`.
- Пути чувствительны к регистру.
- Сегменты декларации и входного pathname декодируются из percent-кодирования. `/hello%20world` и `/hello world` обозначают один статический шаблон.
- Разделение на сегменты происходит до декодирования, поэтому `%2F` не создаёт новый сегмент.
- Некорректное percent-кодирование декларации отклоняется при регистрации; некорректное кодирование входного pathname отклоняется при сопоставлении.
- `?`, `#`, обратный слеш, NUL, управляющие символы и сегменты `.` или `..` запрещены.
- `match` принимает только pathname с начальным `/`; query string и fragment в него не передаются.
- Входной pathname нормализует повторные и завершающие `/` так же, как декларация.

## Динамические сегменты

- Динамический сегмент имеет форму `:name` и занимает сегмент целиком.
- Имя соответствует `[A-Za-z][A-Za-z0-9]*`.
- Пустые имена, подчёркивания, дефисы, точки и смешанные формы вроде `file-:id` не допускаются.
- Имена параметров внутри одного маршрута уникальны.
- Динамический сегмент совпадает ровно с одним непустым сегментом и не поглощает `/`.
- Wildcard-маршруты не поддерживаются.

## Конфликты и приоритет

- Идентичность HTTP-маршрута задаётся HTTP-методом и структурой шаблона пути.
- `/users/:id` и `/users/:userId` конфликтуют для одного HTTP-метода.
- Одинаковые шаблоны для разных HTTP-методов не конфликтуют.
- При пересечении шаблонов статический сегмент выигрывает у динамического на первой различающейся позиции слева направо.
- Порядок регистрации не влияет на результат.
- `HEAD` не использует `GET` автоматически; `OPTIONS` не генерируется автоматически.

## Сопоставление

Успешный `match(method, pathname)` возвращает новый объект следующей формы:

```js
{
  route: {
    method: 'GET',
    path: '/users/:id',
    handler: 'getById',
    controller: UsersController,
  },
  params: {
    id: '42',
  },
}
```

- `route` является сохранённым замороженным определением.
- `params` является новым замороженным обычным объектом при каждом сопоставлении.
- Значения параметров декодированы.
- При отсутствии совпадения возвращается `null`.

## Ошибки

Классы ошибок реализуются в `lib/framework/errors.js`, доступны прямым импортом и поддерживают проверку через `instanceof`:

- `InvalidHttpControllerError extends TypeError` — неверный класс, наследование, метаданные контроллера, обработчик или прямое создание `HttpControllerBase`;
- `InvalidHttpRouteError extends TypeError` — неверное определение маршрута, HTTP-метод, путь или аргументы `HttpRouter`;
- `DuplicateHttpControllerError extends Error` — повторная регистрация класса;
- `HttpRouteConflictError extends Error` — конфликт с каталогом или внутри регистрируемой пачки;
- `InvalidHttpPathEncodingError extends URIError` — некорректное percent-кодирование входного pathname.

Ошибки выбрасываются синхронно. Фреймворк не завершает процесс самостоятельно; незахваченная ошибка естественно прерывает запуск приложения.

## Вне scope

- Библиотечная точка входа и реэкспорты.
- Публичный доступ к `HttpRouter`.
- HTTP-сервер и `Application.run()`.
- Создание экземпляра HTTP-контроллера и выполнение HTTP-обработчика.
- Формирование `HttpRequestContext` и HTTP-ответа.
- Автоматические `HEAD` и `OPTIONS`.
- Wildcard-маршруты.
- Удаление маршрутов и hot reload.
- Ограничение регистрации после запуска приложения; оно будет определено вместе с жизненным циклом.
