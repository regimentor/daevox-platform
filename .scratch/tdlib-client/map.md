# Клиент TDLib для Daevox

Labels: wayfinder:map
Status: resolved

## Destination

Согласованная спецификация самостоятельного типизированного клиента TDLib в `lib/`, достаточная для последующей реализации библиотеки. Подключение к backend не входит в текущую карту.

## Notes

- Планирование по `wayfinder`; реализация не входит в эту карту. Для обсуждения решений применять `grilling` и `domain-modeling`, для исследований — `research`.
- Подтверждено пользователем при определении цели: полный API TDLib, поток обновлений, управление запуском, авторизацией и завершением. Базовая обёртка без обязательного набора высокоуровневых удобных операций.
- Клиент независим от агентских задач. Backend — потребитель; выбор чатов, типов данных, сценариев использования и ограничение чтением принадлежат приложению.
- Предполагаемая точка будущей интеграции с backend — AppState. Детали интеграции не ограничивают контракт библиотеки и сейчас не проектируются.
- Развёртывание self-hosted на текущем личном ПК, один личный Telegram-аккаунт как исходный сценарий. Поддержка других ОС сейчас не требуется.
- Явное ограничение пользователя: zero deps, использовать только Node API. Готовые npm bindings и пакеты поставки TDLib исключены. Подтверждения по способу подключения фиксируются в обсуждении соответствующей задачи контракта.
- Корневые npm workspaces включают `lib/*`. Backend использует ESM и Node >=26. Клиент не добавляет npm runtime-зависимостей; общие dev-инструменты принадлежат корню.
- Трекер: `docs/agents/issue-tracker.md`. У открытых невзятых задач отсутствует `Status`; взятие — `Status: claimed`, завершение — `Status: resolved`. `Blocked by` содержит номера дочерних задач. Детальные ответы хранятся только в задачах.

## Decisions so far

- [Способы подключения TDLib к Node.js на текущем ПК](issues/01-native-interface-research.md): встроенный экспериментальный node:ffi доступен на текущем ПК и даёт путь без npm bindings; интеграция с реальной TDLib пока не проверена.
- [Контракт типизированного клиента TDLib](issues/02-client-contract.md): согласованы submodule + FFI, типизированный invoke, подписки и отмена ожидания без автоматических повторов.
- [Владение сессией и жизненный цикл клиента TDLib](issues/03-session-lifecycle.md): авторизация включая QR управляется приложением; запуск отделён от готовности, close сохраняет сессию и допускает отмену ожидания.
- [Сборка TDLib и соответствие генерируемых типов](issues/04-build-and-types.md): явная сборка workspace, типы в Git, проверка соответствия артефактов и только явные обновления TDLib.
- [Исполнение FFI и доставка обновлений](issues/05-ffi-update-delivery.md): общий worker, последовательные ограниченные очереди подписчиков и явное отключение при ошибке или переполнении.
- [Проверки клиента TDLib перед реализацией](issues/07-client-verification.md): verify с тестами контрактов и реальной TDLib без аккаунта; авторизация проверяется отдельным ручным сценарием.
