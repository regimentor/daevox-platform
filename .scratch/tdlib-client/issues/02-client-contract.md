## Question

Какой способ подключения и публичный контракт выбрать для самостоятельного workspace клиента: типизированные запросы ко всему API TDLib, получение обновлений, ошибки, отмена и поведение незавершённых запросов? Где проходит граница между обёрткой и ответственностью приложения, и как контракт сохраняет соответствие версии TDLib без ручного дублирования всего API?

Выбор обсудить с пользователем на основе исследования. Полный API и отсутствие зависимости от агентских задач уже входят в исходные рамки. Обязательное ограничение: zero deps, только Node API; готовые npm bindings исключены. Сначала установить допустимую границу нативной интеграции с TDLib: собственный addon или вспомогательный процесс не считать разрешёнными без обсуждения.

## Answer

Согласовано с пользователем 2026-09-08:

- Самостоятельный workspace `lib/tdlib`, без npm-зависимостей клиента. Используются встроенные API Node.js; доступ к нативной библиотеке — через экспериментальный `node:ffi` с необходимым флагом запуска.
- TDLib хранится как git submodule в `lib/tdlib/vendor/td` на закреплённом коммите. `libtdjson.so` собирается локально через CMake, артефакты сборки игнорируются Git. Системные сборочные зависимости TDLib допустимы.
- TypeScript-типы генерируются из `td_api.tl` того же коммита; ручная обёртка каждого метода не требуется. Детали сборки и генерации решаются в задаче «Сборка TDLib и соответствие генерируемых типов».
- `invoke(request)` принимает типизированный объект TDLib с `@type` и возвращает `Promise` с автоматически выведенным типом результата. Клиент предоставляет полный API; прикладное ограничение чтением остаётся в приложении.
- `onUpdate(handler)` создаёт независимую подписку и возвращает функцию отписки. Каждый подписчик получает обновления в порядке поступления; ответы на запросы разрешают соответствующие Promise и не подменяют поток обновлений.
- Ошибки отклоняют Promise. Для ошибок TDLib сохраняются исходные код и сообщение.
- Вызовы поддерживают опциональные `AbortSignal` и timeout. Они прекращают ожидание вызывающей стороны и не обещают отменить уже отправленную операцию. Автоматических повторов нет.

Решение о публичной форме принято. Поведение незавершённых запросов при закрытии относится к задаче «Владение сессией и жизненный цикл клиента TDLib»; исполнение FFI и обработка медленных/ошибающихся подписчиков — к задаче «Исполнение FFI и доставка обновлений». Это отдельные открытые решения, а не неявно принятые гарантии.
