## Question

Как организовать воспроизводимую сборку закреплённого TDLib submodule и генерацию TypeScript из его схемы без npm-зависимостей клиента: команды workspace, места артефактов, проверка соответствия схемы и бинарника, обновление закреплённого коммита и поведение при отсутствующей либо устаревшей сборке? Хранить ли генерируемые типы в Git? Учесть native TypeScript и текущий Linux-ПК; не выполнять сборку и реализацию в этой задаче.

Способ поставки уже подтверждён в обсуждении задачи «Контракт типизированного клиента TDLib»; здесь решаются детали его воспроизводимости.

## Answer

Пользователь подтвердил все четыре пункта:

- Подготовка запускается явно командой `npm run build -w @daevox/tdlib`: проверка необходимых инструментов, сборка закреплённой TDLib и генерация типов. Запуск backend не инициирует сборку автоматически.
- Генератор использует только Node API. Сгенерированные TypeScript-типы хранятся в Git и доступны редактору и проверке типов без нативной сборки. Отдельная проверка обнаруживает расхождение генерируемых типов со схемой submodule. Нативные бинарники и промежуточные результаты сборки остаются вне Git.
- Сборка сохраняет сведения о коммите TDLib, схеме и полученном бинарнике. Перед загрузкой клиент проверяет соответствие закреплённой версии и артефактов; отсутствующая либо несовместимая сборка останавливает запуск с понятной ошибкой и командой пересборки. Автоматически подбирать другую системную библиотеку нельзя.
- Обновление TDLib выполняется явно: изменение закреплённого коммита submodule, пересборка и обновление генерируемых типов рассматриваются вместе. Автоматического перехода на свежий master нет.

Конкретный формат метаданных и внутренних каталогов сборки остаётся деталью реализации этих гарантий. Закрепление исходников не означает обещания побайтово одинаковых бинарников на разных toolchain.
