# Способы подключения TDLib к Node.js на текущем ПК

Type: research
Status: resolved
Assignee: tdlib_research
Labels: wayfinder:research
Parent: ../map.md

## Question

Как подключить полный API TDLib и обновления в Node.js на текущем ПК с явным ограничением пользователя: zero deps, только Node API? Проверить встроенный FFI, различие встроенных JS API и собственного Node-API addon, вариант subprocess/helper и наличие штатного executable-протокола TDLib. Не считать собственный C++ helper автоматически разрешённым. Уточнить типы, неблокирующее получение обновлений и границы поставки нативной библиотеки. Не устанавливать зависимости, не собирать компоненты и не обращаться к аккаунту.

## Answer

2026-09-08: после уточнения пользователя прежняя рекомендация готовых bindings отменена. Исследование пересмотрено. Текущий ПК — Arch Linux x86_64, glibc 2.44, Node v26.8.1. Встроенный `node:ffi` существует с Node 26.1.0; его импорт на текущем Node с `--experimental-ffi` успешно проверен. Он умеет C-сигнатуры, загрузку `.so` и UTF-8 pointer/string conversion, поэтому прямой JS/TS-клиент поверх `libtdjson.so` — обоснованный кандидат без npm bindings, addon или helper. Это вывод о выполнимости, не принятый архитектурный выбор.

FFI экспериментальный; само условие Node >=26 недостаточно для 26.0. Для ожидания `td_receive` следует рассмотреть встроенный worker_threads и цикл, который уступает управление для команд send/close. Варианты со своим Node-API addon либо C++ helper требуют иной границы: они не разрешены автоматически. Официальные примеры ссылаются на внешние CLI, штатный универсальный executable-протокол в исследованных источниках не найден. Полная типизация требует решения о генерации из закреплённой схемы; поставка TDLib остаётся отдельной нативной зависимостью.

Следующее решение: допустимы ли экспериментальный `node:ffi`, флаг запуска и отдельно предоставленная TDLib в рамках «только Node API»? Интеграция с реальной `.so`, отзывчивость и закрытие не проверялись; импорт модуля не является проверкой клиента. Пакеты не устанавливались, аккаунт не использовался.
