# Подключение клиента к жизненному циклу backend

Type: grilling
Status: resolved
Resolution: out-of-scope
Assignee: codex
Labels: wayfinder:grilling
Parent: ../map.md
Blocked by: 03

## Question

Как backend владеет экземпляром клиента и подключает start/close к существующим hooks AppState: какие параметры передаёт, доступен ли backend до авторизации Telegram, как представляет неготовность и фатальный сбой потребителям и как ограничивает ожидание остановки? Как приложение получает состояния авторизации, включая обновляемую QR-ссылку, не встраивая UI и агентские сценарии в библиотеку?

Определить минимальный интеграционный контракт, не проектируя продуктовый UI и инструменты агентов. Использовать согласованный lifecycle клиента и существующее решение framework о едином прикладном состоянии.

## Comments

Пользователь исключил подключение к backend из текущего scope. Предполагаемая точка будущей интеграции — AppState. Предложения о запуске HTTP без готового Telegram, поведении при сбоях и HTTP-маршрутах пользователем не согласованы и не являются решениями этой карты.

## Answer

Закрыто как out of scope по явному указанию пользователя. Реализация и спецификация подключения к backend откладываются. Предполагается будущая интеграция через AppState; библиотека остаётся независимой от backend/framework. В Decisions so far эта задача не включается.
