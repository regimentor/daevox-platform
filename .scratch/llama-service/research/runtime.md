## Подтверждено документацией

- Запуск без модели включает router, который запускает экземпляры и маршрутизирует запросы. Самостоятельный запуск с `-m` загружает указанную модель. Router поддерживает `--models-max 1`; autoload включён по умолчанию, отключается `--no-models-autoload`, но также управляется query-параметром запроса.
- Есть `/models/load`, `/models/unload`, `/models/sse` и перечитывание списка через `/models?reload=1`. Reload выгружает изменённые/удалённые работающие модели. Это не обещание автоматического наблюдения за файлами.
- `--models-preset` принимает один INI. Поддерживаются секции моделей, общая секция `[*]`, короткие имена и env-имена ключей; приоритет CLI выше секции модели, затем общих настроек. Относительные пути разрешаются относительно CWD сервера. Часть аргументов контролирует router. `load-on-startup` не загружает новые модели при reload. Каталог нескольких INI как единый источник не документирован.
- `/health` standalone: 503 при загрузке, 200 при готовности. `/metrics` требует `--metrics`; это метрики inference, не полный мониторинг железа. GET-запросы router выбирают модель через query. Логи поддерживают файл, JSONL, timestamps и verbosity.

Источник: [README фиксированного commit](https://github.com/ggml-org/llama.cpp/blob/82d6bb284d1ff1c6ef37f29a4c3b63d1a8b11806/tools/server/README.md), строки 99–107, 229–230, 470–484, 1122+, 1651–2006.

## Уточнено чтением исходников

- LRU scheduler исключает кандидатов с ненулевым `req_count`; когда все заняты, очередь ждёт завершения запроса. Это поведение автоматического вытеснения, не гарантия любого ручного unload.
- Ручной `unload()` загружающегося экземпляра вызывает принудительное завершение. Для работающего экземпляра отправляет команду выхода и запускает таймер; по истечении `stop-timeout` процесс принудительно завершается. Значение по умолчанию по README — 10 секунд.
- HTTP unload возвращает success после постановки остановки, не после подтверждения освобождения памяти. Статус завершения обновляет monitor. Поэтому success нельзя трактовать как «VRAM уже свободна».
- Reload вызывает тот же unload для изменённых/удалённых конфигураций. stdout/stderr дочернего процесса объединены.

Источник: [server-models.cpp](https://github.com/ggml-org/llama.cpp/blob/82d6bb284d1ff1c6ef37f29a4c3b63d1a8b11806/tools/server/server-models.cpp), строки 120–140, 229–236, 265–286, 867–890, 1175–1185, 1236–1260, 2083–2099.

**Граница проверки:** семантика завершения streaming/in-flight запроса после команды выхода в дочернем сервере не прослежена до конца и не проверена экспериментом. Нельзя обещать graceful drain. Не проверены runtime-гарантии `models-max=1` при конкурирующих ручных командах, момент освобождения GPU, восстановление после падения router и поведение router health без активной модели. Это входные вопросы для runtime-решения/последующего прототипа.

## Окружение

Read-only результаты основного агента этой сессии: Arch Linux, kernel 7.2.4; Ryzen 9950X, 16 ядер/32 потока; RAM около 62.1 GiB; PCI NVIDIA RTX 5080 и RTX 4070 Ti, привязаны к nvidia; модуль 615.71.09. Обнаружены nvcc 13.3.73, CMake 4.4.3, GCC 16.2.1, Rust 1.98.1.

В sandbox `nvidia-smi` не связывается с драйвером и отсутствуют `/dev/nvidia*`. Это ограничение наблюдения, **не доказательство неисправности драйвера хоста**. VRAM, температуры, NVML и выполнение CUDA не подтверждены. Эта заметка использует переданный read-only отчёт агента, а не повторный опрос машины.

## Сборка и оставшиеся проверки

Upstream документирует CPU-сборку CMake и NVIDIA CUDA через `-DGGML_CUDA=ON`, требующий CUDA toolkit. Можно явно задать несколько архитектур в `CMAKE_CUDA_ARCHITECTURES`; для данной пары GPU значения нужно подтвердить перед профилем сборки. Vulkan — отдельный backend и набор зависимостей. Наличие nvcc не подтверждает совместимость CUDA с GCC, glibc и драйвером; CMake configure/build и запуск не выполнялись. Vulkan SDK/ICD и прочие зависимости не инвентаризированы: их отсутствие не установлено.

Источник: [инструкция сборки](https://github.com/ggml-org/llama.cpp/blob/82d6bb284d1ff1c6ef37f29a4c3b63d1a8b11806/docs/build.md), разделы CPU, CUDA, Vulkan.

Ничего не устанавливалось; сборок, загрузок весов, изменения драйверов и процессов не было. Остались решения о router/standalone, политике замены/ожидания, допустимых backend и проверках toolchain; исследование их не принимает.
