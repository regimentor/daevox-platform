# Результаты runtime-эксперимента

Дата: 2026-09-13. Пользователь разрешил сборку и запуск в /tmp. Production-код не менялся.

## Окружение и воспроизведение

- llama.cpp commit `82d6bb284d1ff1c6ef37f29a4c3b63d1a8b11806`, llama-server b10918.
- NVIDIA 615.71.09, RTX 5080 + RTX 4070 Ti; CMake 4.4.3; CUDA 13.3.73; C++ GCC 16.2.1; CUDA использовала установленный GNU 15.3.0 автоматически. Никаких установок и обхода проверки версии компилятора.
- Успешно: `cmake -S llama.cpp -B build-default -DGGML_CUDA=ON '-DCMAKE_CUDA_ARCHITECTURES=89;120' -DLLAMA_CURL=OFF`, затем `cmake --build build-default --target llama-server -j 8`. llama.cpp нормализовала 120 в 120a. NCCL отсутствует: конфигурация предупреждает о возможной потере производительности нескольких GPU; генерация на обеих прошла. Это не измерение производительности.
- Публичный `bartowski/SmolLM2-135M-Instruct-GGUF`, revision `09816acd5d99df7be770d85ea30822623dab342c`, файл `SmolLM2-135M-Instruct-Q4_K_M.gguf`, около 105,5 МБ. SHA256 `2e8040ceae7815abe0dcb3540b9995eaa1fa0d2ca9e797d0a635ae4433c68c2d`.
- Два пресета одних весов: a (2048 context), b (4096 context), один слот, 4 CPU threads, 99 GPU layers. Router: loopback, свободный порт, models-max=1, no-models-autoload; load-on-startup=false. stop-timeout=3 для короткой проверки принудительной остановки (не новое продуктовое значение).
- Скрипты: Python — HTTP/процессы/потоки и минимальная модель управляющей политики; Rust без внешних crates — владение директорией через File::try_lock и дочерний router. Это не реализация Tokio/Axum core.

## Уточнения для спецификации

1. GPU связывать по UUID/PCI, не по совпадению числовых индексов. В этом запуске nvidia-smi 0 = RTX 5080, но CUDA0 = RTX 4070 Ti. В первом проходе ошибочный индекс был замечен по --list-devices; основной проход повторён с CUDA0. Первый проход не используется как подтверждение работы именно на 4070 Ti.
2. Успех `/models/unload` означает принятие команды. Граница следующей загрузки — подтверждённое завершение экземпляра; GPU allocations его PID используются как дополнительное наблюдение. Общая занятая VRAM не обязана совпадать с исходной из-за desktop-процессов.
3. Core закрывает допуск новых запросов и выполняет drain до unload; force сначала прерывает принадлежащие core запросы. Сбой потока нельзя считать успешным завершением генерации.
4. Запуск core должен проверять оставшийся router до создания нового. Идентичность в прототипе: PID, start time, boot ID, executable. Production-механизму нужны проверка всей идентичности и безопасный дескриптор процесса (например pidfd), чтобы исключить гонку повторного использования PID. Прототип демонстрирует блокировку по записи, не готовый механизм безопасного удаления orphan-процессов.
5. Дочерние PID router нужно искать по всем `/proc/<pid>/task/*/children` либо использовать контролируемую группу/другой механизм: child создаётся не обязательно главным потоком. Первый проход с children только главного потока дал пустой список; сбор исправлен и измерения повторены с непустыми PID.
6. Сохранять фактически выбранные C++/CUDA host compiler и архитектуры в fingerprint/логах сборки. Установленный GCC по умолчанию и используемый nvcc host compiler здесь различались.

## Границы доказательства

Один маленький текстовый GGUF, два пресета одних весов. Не проверены большие модели, мультимодальные проекторы, смена разных архитектур, OOM, устойчивость к длительной нагрузке, все аварийные гонки и адаптеры Tokio/Axum/NVML/hf-hub. Минимальная политика драйвера подтверждает порядок операций на реальном router, но не заменяет проверки будущего backend. Вопросы конкретных Rust-адаптеров остаются в отдельной задаче карты.

## Завершение и артефакты

Все процессы inference и Rust-владельцы эксперимента завершены. Финальный nvidia-smi содержит только прежний процесс Chromium; модельных PID нет. В /tmp/daevox-llama-runtime-validation оставлены исходники (~233 МБ), сборка (~854 МБ), веса (~101 МБ), скрипты и логи; веса и бинарники в Git не добавляются.

Воспроизводимые скрипты, итоговый results.json и логи сохраняются в отдельной ветке `codex/prototype-llama-runtime`, каталог `experiments/llama-runtime/`. Исправленный основной проход дополнен отдельной проверкой аварии Rust-владельца с активной моделью; это отражено дополнительными записями results.json.
