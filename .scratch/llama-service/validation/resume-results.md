# Настоящая докачка файлов

2026-09-13. Пользователь выбрал проверку настоящей докачки вместо restart-only.

## Проверенный механизм

Одноразовый Rust executable на reqwest 0.13.5. Самостоятельный процесс читает service-local metadata (исходный URL с фиксированным revision, ETag, полный размер), определяет смещение по фактической длине partial, заново разрешает исходный URL при каждом запуске. Для продолжения посылает Range и If-Range. Перед дописыванием требует HTTP 206 и точный Content-Range с ожидаемыми смещением и общим размером; сверяет ETag. Запрошен identity encoding, закодированный ответ отклоняется. Файл имеет имя model.partial; после полного успешного чтения переименовывается в model.gguf. Пауза синхронизирует записанные данные и завершает worker; новый процесс продолжает по partial.

Это эксперимент с протоколом и процессной границей. Не реализованы production API операций, общий manifest модели, многокомпонентные наборы и все восстановительные гонки. Параллельные writer должны исключаться согласованной очередью и владением операцией в core.

## Локальные фикстуры

Точный детерминированный файл 4194304 байта:
- Первый процесс сохранил 524288 байт и завершился на паузе.
- Второй послал Range bytes=524288-4194303 и If-Range, получил 206, скачал 3670016 оставшихся байт. Итог побайтно равен исходнику.
- Сервер игнорирует Range и отвечает 200: adapter сообщает, что нужен явный restart; partial не меняется, full response не дописывается к префиксу.
- Неверный Content-Range, HTTP 416 и изменившийся ETag: операция отклонена, partial не изменён, готовый файл не опубликован.

## Реальный Hugging Face

Тот же публичный GGUF 105454432 байта: bartowski/SmolLM2-135M-Instruct-GGUF, revision 09816acd5d99df7be770d85ea30822623dab342c, SmolLM2-135M-Instruct-Q4_K_M.gguf. Без токена.

Первый процесс: HTTP 200, сохранено 4198282 байта, пауза.
Второй процесс: HTTP 206, Content-Range `bytes 4198282-105454431/105454432`, получено ровно 101256150 байт. SHA256 полного результата `2e8040ceae7815abe0dcb3540b9995eaa1fa0d2ca9e797d0a635ae4433c68c2d` совпал с предыдущей полной загрузкой.

SHA256 использован для проверки эксперимента, а не для введения ранее исключённого отдельного продуктового сценария integrity-проверок.

## Предложение для спецификации

Оставить hf-hub 1.0.0 для Hub metadata/search; скачивание выбранных файлов передать отдельному Rust worker с контролируемым HTTP Range-путём на reqwest. `hf-hub.local_dir` не использовать для обещания докачки. Даже у hf-hub.download_file_stream(range) обычная HTTP-ветка не предоставляет вызывающему коду статус/Content-Range и в просмотренном коде не проверяет 206: одного указания range недостаточно для гарантии корректного дописывания.

При поддержке сервером диапазонов продолжать с сохранённого смещения. Если сервер диапазон проигнорировал/объект изменился — сохранять partial, показывать причину и отдельное действие restart, не уничтожать его и не начинать полный файл молча. Отсутствующий/слабый валидатор, неизвестный размер и 416 требуют явного разрешения состояния; этот минимальный стенд отказывается продолжать. Надёжный fallback и пользовательские сообщения должны войти в приёмку реализации.

Проверка одного файла не гарантирует поддержку Range всеми будущими источниками. Для нескольких shard/projector нужны отдельные offsets/идентичности в общем комплекте; сетевой путь Xet отдельно не проверялся и не требуется для подтверждённого HTTP Range-пути.
