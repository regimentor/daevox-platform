# Локальный сервис llama.cpp на Rust

Status: resolved
Labels: wayfinder:map

## Destination

Согласованная спецификация локального сервиса управления llama.cpp на Rust и его интерфейса в существующем веб-клиенте Daevox. Карта завершена, когда разрешены продуктовые и архитектурные вопросы, определены контракты и критерии приёмки, достаточные для последующей реализации.

## Notes

- Исходные требования пользователя и ответы от 2026-09-13: backend на Rust; сервис только для этой машины; интерфейс в существующем apps/web-client; одновременно только одна активная модель; потребители — веб-клиент и локальные приложения. Удалённые устройства не входят в текущий сценарий доступа.
- llama.cpp хранится как Git submodule. Сервис сам собирает его под текущее железо и установленное окружение; модели скачиваются в директорию сервиса и исключаются из Git. Поиск моделей через Hugging Face; настройки моделей через INI-пресеты llama.cpp; каталог INI подключается через интерфейс. Нужны загрузка, выгрузка и замена модели, логи llama-server, состояние всех GPU, CPU, RAM и графики; срок жизни данных уточнён в решении о наблюдении.
- Карта планирует спецификацию; production-код и установка системных зависимостей не входят в scope. Пользователь разрешил изолированный runtime-эксперимент в /tmp: сборку закреплённого llama.cpp, публичный GGUF до 1 ГиБ и проверку процессов/GPU без остановки действующих сервисов; условия в validation/runtime-plan.md.
- Принятые решения находятся в дочерних задачах ниже; варианты из прежнего обсуждения не заменяют их.
- Существующие потребители LLM — секретарь и сервис медиа; новый сервис не получает права останавливать их процессы или менять конфигурацию в ходе планирования. См. [карту контекстов](../../CONTEXT-MAP.md).
- Термины планируемого контекста: [глоссарий](CONTEXT.md). Скачанный комплект, сохранённый пресет и активный экземпляр различаются.
- Навыки: wayfinder; grilling и domain-modeling для решений; research для первичных источников; hf-cli при исследовании Hugging Face; prototype при согласовании интерфейса. Один HITL-ticket за последующую сессию, исследования можно разрешать параллельно.
- Трекер: [правила](../../docs/agents/issue-tracker.md). Открытая невзятая задача не имеет Status; взятие — Status: claimed, завершение — Status: resolved. Assignee обозначает исполнителя. Blocked by содержит номера блокирующих задач, Parent — ссылку на карту. Фронтир: открытые невзятые задачи, все зависимости которых resolved; порядок по номеру. Answer — единственное место решения, карта хранит краткий указатель.
- Исследования сохраняются на отдельных временных ветках research/llama-service-*; результаты и указатели на commit/ветку связываются из исследовательской задачи. Исследования устанавливают факты и ограничения, но не принимают продуктовые решения за пользователя.

## Decisions so far

- [Возможности llama.cpp и окружения этой машины](issues/01-runtime-research.md): изучен фиксированный upstream commit; подтверждение unload асинхронное, гарантии завершения запросов и CUDA на хосте требуют проверки.
- [Интеграции Rust с Hugging Face, метриками и веб-клиентом](issues/02-rust-integrations-research.md): установлены доступные интеграции и существующие контракты Daevox; отмена/resume загрузок, NVML и INI roundtrip требуют проверки выбранных адаптеров.

- [Граница управления llama-server и состав Rust-backend](issues/03-runtime-boundary.md): расширяемый apps/core на Rust с Tokio/Axum и аппаратными адаптерами; штатный router, единый вход через core.

- [Одна активная модель: переключение, запросы и восстановление](issues/04-model-lifecycle.md): ручное управление через web-client, последовательная замена, ожидание запросов до настраиваемых 300 секунд; без автозагрузки и автоматического возврата.

- [Автосборка llama.cpp и граница системных изменений](issues/05-build-lifecycle.md): версия из submodule, автоматическая подготовка CUDA-сборки установленным toolchain; 8 заданий по умолчанию, применение и откат вручную.

- [Каталог Hugging Face и локальное хранение моделей](issues/06-model-catalog.md): публичные GGUF-комплекты с фиксированным commit в apps/core/data/, очередь по одному комплекту, пауза/отмена и ручное удаление.

- [Каталог INI-пресетов и применение настроек модели](issues/07-preset-directory.md): фиксированный apps/core/presets/ в Git, текстовый редактор, локальные общие настройки и явное применение с сохранением работающей конфигурации.

- [Логи, аппаратные метрики и глубина истории](issues/08-observability.md): метрики в памяти текущей сессии core, графики за 60 минут; сохраняемые логи с общей ротацией 200 МиБ.

- [API сервиса и подключение локальных потребителей Daevox](issues/09-api-integration.md): /core/ для web-client, /v1 с конкретным пресетом, локальный доступ без ключей, HTTP/SSE и генерируемый клиент; повторы операций и версии INI.

- [Хранение состояния, запуск и восстановление сервиса](issues/10-storage-startup.md): SeaORM/SQLite с миграциями и резервированием, ручной Cargo-запуск, восстановление без автопродолжения и один core на директорию данных.

- [Управление моделями в существующем веб-клиенте](issues/11-ui-workflow.md): утверждён вариант A; библиотека отдельно, запуск пресетов из action bar, редактирование INI и наблюдение в управлении.

- [Проверка выбранного runtime и сборки на этой машине](issues/13-runtime-validation.md): эксперимент принят; CUDA работает, unload асинхронный, core выполняет drain и проверяет оставшиеся процессы.

- [Проверка загрузчика, INI и доставки наблюдений](issues/14-adapter-validation.md): приняты hf-hub metadata + Rust/reqwest worker с докачкой, диагностика INI и Vite для первой версии.

- [Спецификация сервиса и критерии приёмки](issues/12-spec-acceptance.md): пользователь утвердил спецификацию первой версии и 29 сценариев приёмки; цель карты достигнута.

## Out of scope

- Несколько машин, удалённые агенты и кластерное планирование: сервис предназначен только для этой машины.
- Несколько одновременно активных обслуживающих моделей и отдельная draft-модель: граница установлена в [жизненном цикле модели](issues/04-model-lifecycle.md).
- Новый самостоятельный веб-клиент: используем существующий apps/web-client.
- Реализация и развёртывание приложения: эта карта заканчивается согласованной спецификацией.

- Авторизованный доступ к private/gated-моделям и настройка HF-токена исключены из первой версии: выбран публичный каталог, см. [решение о каталоге](issues/06-model-catalog.md).
- Предложенный сценарий свободного места, резерва и дополнительных проверок готовности пока не рассматривается по указанию пользователя; см. [границу решения о каталоге](issues/06-model-catalog.md). Не превращать его в обязательную задачу без расширения scope.

- Долговременная история метрик и их запись на диск исключены: [решение о наблюдении](issues/08-observability.md). Это не относится к согласованному хранению логов.

- Systemd, автозапуск и автоматический перезапуск core пока исключены: выбран [ручной запуск через Cargo](issues/10-storage-startup.md).

- Production reverse proxy отложен: первая версия web-client через Vite dev server, см. [решение об адаптерах](issues/14-adapter-validation.md).
