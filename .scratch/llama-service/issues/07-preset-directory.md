## Question

Подключаем серверный каталог с наблюдением или импортируем папку из браузера; какие операции редактирования нужны? Как сохраняем семантику INI выбранного llama.cpp, глобальные секции, относительные пути, неизвестные ключи и комментарии? Как объединяем несколько файлов, разрешаем коллизии имён и связываем пресет с локальными весами? Как различаем сохранённые и применённые параметры, обрабатываем внешнее редактирование и применяем изменения к активной модели? Что делать с исчезнувшим каталогом, повреждённым INI и устаревшей версией параметров?

## Comments

Первый раунд: «1. папку выбирает core, хардкод проекта; 2. да; 3. да; 4. да».
Второй раунд: «1 окей; 2 ок; 3 окей; 4 окей» на предложения о пути/Git, общих настройках и путях, ошибках и конфликте редактирования.

## Answer

1. **Фиксированный каталог.** Core использует заданный проектом apps/core/presets/. Выбора произвольной папки пользователем и импорта папки из браузера нет. Core читает INI и отслеживает внешние изменения.
2. **Git и генерируемые файлы.** Исходные INI хранятся в Git. Изменения через web-client — локальные изменения файлов; автоматических коммитов нет. Итоговый INI для router генерируется отдельно внутри apps/core/data/, исключённой из Git. Генерация не переписывает исходные файлы.
3. **Организация.** Один INI-файл на модель, несколько именованных пресетов внутри, например с разными размерами контекста. Пресеты могут использовать одни скачанные веса. Конфликт имён пресетов при формировании общего каталога — явная ошибка, без молчаливого переопределения. Поддержка произвольного объединения нескольких моделей в одном исходном файле не выбрана.
4. **Редактор.** Web-client предоставляет текстовый INI-редактор: создание, редактирование, сохранение и отображение ошибок рядом с текстом. Комментарии и оформление исходного текста сохраняются. Структурированные формы параметров пока не входят в решение. В редакторе можно выбрать скачанный комплект модели, чтобы core подставил путь к весам.
5. **Общие настройки.** Секция [*] исходного файла относится только к пресетам этого файла. При генерации общего INI core сохраняет такую область действия, а не распространяет общие настройки одного файла на остальные. Механизм объединения и приоритетов проверяется на выбранной версии llama.cpp.
6. **Пути.** Относительные пути к файлам в исходном INI разрешаются относительно директории этого INI. В итоговом INI они преобразуются в абсолютные. Это семантика исходного каталога core; она отличается от разрешения путей относительно CWD у самого llama-server. Нельзя трактовать произвольное строковое значение как путь: покрытие соответствующих параметров проверяется прототипом.
7. **Сохранение и применение.** Сохранение либо внешнее изменение обновляет каталог, но не перезапускает активную модель. UI показывает неприменённые изменения. Явное «Применить» для активного пресета запускает [согласованную процедуру переключения](04-model-lifecycle.md). Применённая конфигурация и текущий текст исходника различаются; изменение исходника само по себе не запускает router reload, способный выгрузить модель.
8. **Ошибки и черновик.** Некорректный INI разрешается сохранить как черновик, но применить нельзя. Ошибка или удаление исходного файла не останавливает работающую модель: она продолжает с применёнными настройками, UI показывает расхождение. Неподдерживаемые параметры показываются как ошибка применения и не удаляются молча. Обработка ключей, которые router контролирует сам, должна согласовываться с этим правилом в API/валидации, а не скрывать потерю пользовательской настройки.
9. **Конфликт редактирования.** Если исходник изменился извне при наличии несохранённых правок в UI, показывается конфликт. Пользователь выбирает перечитать файл либо явно заменить его своей версией; автоматической перезаписи внешних изменений нет. Точный механизм версий/условной записи определяется API-контрактом.

Продолжение: [API сервиса](09-api-integration.md), [хранение состояния](10-storage-startup.md), [интерфейс управления моделями](11-ui-workflow.md), [проверка загрузчика, INI и доставки наблюдений](14-adapter-validation.md). В текущей сессии изменены только документы трекера; apps/core/presets и приложение пока не создаются.

Уточнение после проверки адаптеров, принято пользователем: повтор секции блокирует применение, повтор ключа даёт предупреждение с указанием итогового (последнего) значения. Исходник по-прежнему можно сохранить как черновик. Проверка upstream-поведения: [результаты](../validation/adapter-results.md).
