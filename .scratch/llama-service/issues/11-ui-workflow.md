## Question

Как разместить каталог моделей, активную модель, пресеты, сборку, логи и системные графики в существующем веб-клиенте? На минимальном прототипе согласовать загрузку весов, переключение активной модели, ошибку сборки, изменение INI и восстановление соединения. Прототип — материал для обсуждения, не production-реализация. Ответ принимает пользователь; новые исследования или решения выделять по обнаруженным пробелам.

## Prototype

Создан отдельный throwaway UI-прототип в оболочке существующего web-client (Mantine/AppHeader), без изменений кода приложения в основном checkout.

- Ветка: codex/prototype-llama-core; утверждённый commit 037b83d (исходные три варианта — f2ec6a4).
- Worktree: /tmp/daevox-core-ui-prototype.
- Инструкция и ограничения: apps/web-client/CORE-PROTOTYPE.md в указанной ветке.
- Запуск из worktree: npm run prototype:core --workspace @daevox/web-client.
- Просмотр: http://127.0.0.1:5175/prototype/core?view=manage ; выбран A, переключатель и варианты B/C удалены из текущего прототипа, сохранены в истории ветки.
- A — обзор и вкладки; B — боковая навигация/каталог/инспектор; C — операции и постоянная консоль.

Все данные и операции демонстрационные, состояние только в памяти. Доступны сценарии ожидания/отмены/принудительной замены, скачивания с паузой, ошибки сборки, редактирования INI/конфликта и потери связи. Backend, Hub, процессы и GPU не вызываются. Ручная браузерная проверка подтвердила загрузку страницы, три компоновки, ожидание перед заменой и отмену с сохранением старой модели.

Ограничения: это проверка компоновки, не полная спецификация всех элементов. Применение сборки в макете после отдельной выгрузки; итоговая реализация должна следовать согласованному жизненному циклу. Валидация INI демонстрационная, метрики иллюстративные, полный набор сенсоров/операций не реализован. Typecheck workspace показывает существующий конфликт react-markdown/remark-gfm/vfile в DailySummaries.tsx; ошибок в новых файлах прототипа не показано.

## Answer

Пользователь утвердил интерфейс 2026-09-13 после выбора варианта A и внесения правок.

- Компоновка A: обзор активной модели и машины, ниже вкладки «Пресеты», «Система», «Сборки», «Логи».
- Пункт header «Модели LLM» открывает только библиотеку моделей и скачивание публичных моделей из Hugging Face.
- Постоянный action bar в header в стиле macOS показывает активный пресет и TPS; отсутствие измерений обозначается «—». Его раскрытие содержит выбор, запуск, смену и перезапуск сохранённого пресета, а также ссылку на управление моделями.
- В разделе «Пресеты» только редактирование и сохранение INI. Сохранение не перезапускает модель; применение сохранённых изменений запускается из action bar. Карточка «Выбранный пресет» удалена, редактор занимает доступную ширину.
- Скачивание HF показано отдельным временным action bar: имя, справа круговой прогресс с процентами внутри. Высота и отступы совпадают с панелью активной модели. В раскрытии доступны пауза, продолжение, отмена и библиотека; панель остаётся на паузе и исчезает после завершения или отмены.
- Логи сборки видны во время сборки непосредственно в её разделе; доступны автопрокрутка и скачивание вывода. Общие логи и наблюдение за системой остаются отдельными вкладками.

Источник утверждённого решения: ветка `codex/prototype-llama-core`, commit `037b83d`, инструкция `apps/web-client/CORE-PROTOTYPE.md`. Браузером проверены запуск пресета и последовательная замена через action bar. Это утверждение интерфейса, не подтверждение runtime-контрактов и не разрешение на production-реализацию: дальнейшая проверка runtime и адаптеров остаётся в отдельных задачах карты.
