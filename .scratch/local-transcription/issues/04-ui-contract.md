## Question

Как интегрировать отдельный Python/uv-сервис с текущим web-client и npm orchestration: маршрутизация, конфигурация, локальная граница доступа, загрузка больших файлов? Как выглядит контракт запуска, состояния, событий и ошибок, включая переподключение UI и пропущенные события? Как UI показывает подготовку, первую загрузку модели, реальный прогресс и добавление текста без фиктивных процентов? Зафиксировать границы модулей и проверяемые современные практики Python/FastAPI.

Также определить точную схему JSON с временными метками, представление отменённой операции и судьбу её частичного текста. Восстановление после перезапуска бэкенда и история прошлых запусков исключены пользователем; переподключение UI к текущей операции остаётся в области решения.

## Comments

### Согласование UI и дополнение о спикерах

- Приняты форма «файл / YouTube», язык, запуск, этап, прогресс, появляющийся текст и отмена.
- Приняты этапы передачи/получения источника, подготовки, загрузки модели, распознавания, сохранения; измеримые проценты, позиция записи без обещания точного ETA.
- При отмене распознанный текст остаётся в UI и сохраняется с отметкой неполного результата; временные файлы удаляются, GPU освобождается.
- Последний результат и пути TXT/JSON доступны до следующего запуска или перезапуска сервиса, без истории.
- Обязательно разделение по спикерам. Ранее предложенное исключение диаризации отвергнуто; схема сегментов должна учитывать метки спикеров. Уточнение поведения и исследование вынесены в дочерние задачи карты.
- Приняты отдельный apps/transcription-backend, HTTP-команды, SSE-обновления и отдельный процесс GPU-обработки.
- Пользователь явно указал proxy в apps/web-client/vite.config.ts с начальным slug `/trancription-api/` (написание точное). Этот префикс заменяет предложенный `/api/transcriptions` для обращений UI.
- Последующее уточнение: ASR и диаризация могут работать на разных GPU параллельно. Контракт прогресса должен поддерживать независимые состояния этих этапов; обязательная последовательность ASR → диаризация не согласована.
- Передача локального файла требует открытой вкладки до завершения upload; затем обработка независима от вкладки. Для YouTube достаточно принятия ссылки бэкендом.

## Answer

Контракт зафиксирован в [Контракте API и UI транскрибации](../api-ui-contract.md): форма отдельной вкладки, точный Vite proxy `/trancription-api/`, HTTP-команды, snapshot/SSE с ревизиями, независимые этапы двух GPU, схема результатов и обработка отмены. Документ содержит техническую конкретизацию принятых требований, не результаты реализации.

Пользователь подтвердил последние продуктовые правила: при ошибке диаризации ASR продолжается с сохранением текста и предупреждением; наложение голосов отмечается с сохранением интервалов спикеров в JSON без гарантии восстановления каждой реплики; смена спикера внутри Whisper-фразы определяется по внутренним временным меткам слов, без дополнительной alignment-модели.

Связанные решения о локальных моделях и назначении GPU остаются в соответствующих задачах. Реальная совместимость, качество и ресурсные характеристики должны быть проверены при приёмке. Следующий шаг — итоговая спецификация и критерии её проверки.
