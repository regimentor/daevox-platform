# Контракт API и UI транскрибации

Статус: согласован в задаче «Контракт FastAPI и вкладки транскрибации». Пользователь подтвердил предложенные правила ошибки диаризации, перекрывающейся речи и смены спикера внутри фразы. Этот документ конкретизирует интерфейсы для реализации; реальные GPU-проверки ещё не выполнены.

## Граница сервиса

- Python-приложение apps/transcription-backend: Python 3.12, uv, pyproject.toml, uv.lock, src layout, FastAPI, Pydantic-модели входа/выхода, типизация, структурированные логи с operation_id. Ruff, проверка типов и pytest включены в workspace-команды через npm-обёртку; Python-зависимости принадлежат pyproject.
- Сервис по умолчанию слушает 127.0.0.1:3001; адрес настраивается. Один API-процесс владеет текущей операцией; два отдельных GPU-процесса выполняют ASR и диаризацию. Модель не создаётся при импорте или старте сервера. Отдельной очереди нет.
- Vite proxy для `/trancription-api/` направляет запросы на Python-сервис, сохраняя префикс; target задаётся конфигурацией. Существующий `/api` остаётся маршрутом текущего backend. Для собранного web-client требуется аналогичный reverse proxy, включая SSE без буферизации.
- Вкладка `/transcription` использует существующий AppHeader и компоненты Mantine. HTTP-команды и SSE идут с того же origin через proxy.

## HTTP

Все пути имеют префикс `/trancription-api/`.

| Метод и путь | Контракт |
| --- | --- |
| POST operations | JSON: source_kind=file/youtube, filename либо url, language=auto/ru/en, client_request_id. Атомарно резервирует единственный запуск и возвращает 201 с operation_id/snapshot. Занято — 409. Повтор того же client_request_id текущей операции возвращает её snapshot. |
| PUT operations/{id}/source | Поток тела выбранного файла на диск; без накопления целиком в RAM. Только для file в состоянии awaiting_upload. Окончание тела запускает подготовку. Повторная передача для уже принятого источника отклоняется. |
| GET operations/current | Snapshot текущей/последней операции или null. Нет списка истории. |
| GET operations/{id} | Snapshot известной текущей/последней операции; 404 для вытесненной операции. |
| GET operations/{id}/events | SSE: snapshot, stage, transcript, terminal; монотонный event id/revision. |
| POST operations/{id}/cancel | Идемпотентный запрос отмены, 202 и snapshot. Терминальная операция возвращается без изменения результата. |
| GET health | Проверка API без загрузки весов или модели. |

Для file веб-клиент после резервирования немедленно передаёт файл; разрыв upload завершает этот запуск ошибкой и удаляет временную копию. Резервация без начатой передачи имеет технический таймаут, не лимит длительности медиа. Для YouTube обработка начинается после принятия ссылки. Обрабатывается одно готовое публичное видео, не весь playlist.

## Snapshot и события

Snapshot: operation_id, revision, status, source, language_requested, language_detected, stages, transcript_revision, segments, speaker_turns, speakers, completeness, output_paths, error.

- status: awaiting_upload / running / cancelling / completed / cancelled / failed.
- stages: acquisition, preparation, asr_model, diarization_model, asr, diarization, saving. У каждого state (pending/running/completed/cancelled/failed), completed_units, total_units nullable и unit. ASR и диаризация имеют независимый прогресс.
- Для upload/download показываются байты при известном total, подготовки — обработанная длительность, ASR — позиция в записи (оценка, не ETA), диаризации — доступный прогресс внутренних этапов. Если denominator неизвестен, индикатор неопределённый; общий фиктивный процент не вычисляется.
- Сегмент: id, start/end в секундах от начала источника, text, speaker_id nullable, speaker_status=pending/assigned/unknown, overlap. До готовности диаризации UI пишет «Спикер определяется», а не выдаёт отсутствие разметки за неизвестного спикера.
- transcript-событие содержит revision и атомарную замену изменённого диапазона сегментов: спикер может смениться внутри исходного Whisper-сегмента, поэтому только append недостаточно. Новая разметка никогда не меняет уже распознанные слова без явной ASR-ревизии.
- Подписка регистрируется атомарно со snapshot. При reconnect Last-Event-ID позволяет воспроизвести доступный хвост; при пропуске или переполнении ограниченного журнала отправляется новый snapshot. События со старой revision игнорируются. Медленный клиент не блокирует GPU-процессы.
- Закрытие SSE не отменяет работу. После возвращения вкладка получает current и подписывается заново. Полный текст доступен через snapshot; представление длинного текста в UI должно оставаться отзывчивым.

## Спикеры и файлы

Предлагается использовать внутренние word timestamps Whisper для совмещения с временными интервалами Community-1 и разделять отображаемые фразы при смене говорящего. Отдельная модель alignment пока не добавляется; качество границ проверяется на приёмке. Слова отдельно в UI не показываются.

JSON schema_version=1: operation_id, source (тип, имя/URL), language, models (id/revision), status, completeness (asr, diarization), speakers (id/label), segments и speaker_turns. speaker_turns сохраняет исходные интервалы диаризации, включая наложения; сегмент текста имеет одну основную метку по временному пересечению и overlap=true при наложении в любой части реплики. Соседние части речи одного назначенного спикера объединяются до смены говорящего независимо от границ ASR, пауз и изменения overlap. Если привязки нет, speaker_id=null и status=unknown. Реальные имена не устанавливаются, ID нормализуются по первому появлению голоса внутри записи.

TXT: название источника, отметка неполноты при необходимости, затем блоки вида `[00:01:23] Спикер 1: текст`. Для наложения — отметка «Одновременная речь»; разделение аудио на независимые голоса не обещается.

Каталог результата: безопасное название источника + уникальный operation_id в настраиваемой папке данных. Итоговые TXT/JSON записываются через временный файл и атомарную замену. completed публикуется только после сохранения обоих файлов. Сбой записи не выдаётся за успех; UI показывает текст, ошибку и лишь реально сохранённые пути. Пользовательские оригиналы не удаляются.

## Отмена и ошибки

- Отмена останавливает оба процесса, сохраняет уже принятые сегменты и доступную разметку как неполный результат; отмена до первого текста сохраняет метаданные и пустой неполный текст. Освобождение GPU и удаление временных копий предшествуют разрешению нового запуска.
- Ошибка диаризации не прерывает исправно работающий ASR: сохранить весь доступный текст, completeness.diarization=false, общий результат failed с пояснением «Текст сохранён, спикеры не определены». Недостающие метки не выдумывать. Автоматического повторного запуска нет.
- Ошибка ASR останавливает оставшуюся работу и сохраняет принятый частичный текст, если сохранение возможно. GPU/disk/network/source ошибки сообщаются по месту. Это обработка ошибки живой операции, не восстановление после перезапуска backend.
- Искусственных ограничений размера/длительности нет. При исчерпании ресурсов сообщается реальная ошибка; неизменный расход RAM для произвольно длинного файла не обещается. Глобальная диаризация сохраняет общий контекст голосов; независимое присвоение ID по чанкам недопустимо.
- Секрет доступа к весам хранится в серверной конфигурации, не попадает в UI, JSON, логи или URL. Первое скачивание только после запуска пользователем; отсутствие доступа отображается явно.

## Проверки контракта

Атомарное исключение второго запуска; upload/disconnect; отмена обоих процессов; snapshot/SSE без пропусков и дубликатов; независимые стадии двух GPU; ревизии разметки; частичный результат и ошибки сохранения; Vite proxy с точным написанием префикса. Реальный GPU, качество речи/спикеров и потребление ресурсов проверяются отдельно при реализации, не считаются подтверждёнными этим документом.
