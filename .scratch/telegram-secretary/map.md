# Секретарь: выбор Telegram-чатов и архив сообщений

Labels: wayfinder:map
Status: resolved

## Destination

Согласованные решения и спецификация первого этапа секретаря: выбор Telegram-чатов в веб-клиенте и устойчивое локальное сохранение сообщений для последующей обработки агентом. Карта завершена, когда требований достаточно для реализации backend, UI и хранилища без оставшихся продуктовых и архитектурных вопросов.

## Notes

- Пользователь согласовал границы ниже 2026-09-09 в ответах Q1–Q5. Это исходные требования карты, а не разрешённые дочерние задачи. Карта планирует работу; реализация приложения выполняется отдельно.
- Локальный Daevox, один подключённый личный Telegram-аккаунт, без отдельной учётной записи пользователя backend. Основание: [Подключение личного Telegram-аккаунта через QR](../telegram-qr-auth/map.md).
- Доступны личные переписки и группы, включая архивные. Каждый Telegram-чат включается явно, по умолчанию наблюдение выключено.
- Сохраняются входящие сообщения и собственные ответы пользователя.
- Сбор начинается с момента включения наблюдения, без более ранней истории. Сообщения, пропущенные при выключенном Daevox во время наблюдения, догружаются после запуска.
- Сохраняются текст, подписи к вложениям, автор, время, связь с сообщением, на которое отвечают; для вложений — тип и идентификаторы. Исходное требование — учитывать правки и исключать удалённые сообщения из будущей обработки.
- Выключение наблюдения останавливает дальнейший сбор и сохраняет накопленный архив.
- Уточнения исходных требований — повторное включение, смена аккаунта, пределы актуальности, допустимые действия и состав первой версии — зафиксированы в [Жизненном цикле наблюдения и границах полноты архива](issues/02-observation-lifecycle.md).
- Секундная точность границ и исключение для недостоверного продолжения авторизации уточнены в [Контракте настроек и алгоритме сбора сообщений](issues/05-ingestion-contract.md).
- Будущий агент будет работать через локальную модель в llama.cpp. Этот этап подготавливает архив; сохранение переписки само по себе не означает извлечение памяти.
- Пользователь предложил `packages/db` для локального хранения. На момент исследования каталог пуст и не содержит `package.json`; готового интерфейса хранилища нет. Telegram-подключение и поток TDLib уже существуют, прикладные список чатов и сбор сообщений отсутствуют. Решение о будущем хранилище находится в [Модели архива и локальном хранилище секретаря](issues/03-archive-storage.md).
- Применять `grilling` и `domain-modeling` для обсуждений, `research` для первичных источников, `prototype` для сценария UI. Использовать «Telegram-чат», чтобы отличать его от чата с платформой; «архив Telegram-сообщений» отличать от памяти пользователя.
- Трекер: `docs/agents/issue-tracker.md`. Открытая невзятая задача не имеет Status; взятие — `Status: claimed`, завершение — `Status: resolved`. Blocked by содержит номера дочерних задач. Ответ хранится в Answer задачи, карта содержит только краткий указатель. При выборе следующей задачи брать первую открытую, незаблокированную и невзятую по номеру.

## Decisions so far

- [Гарантии TDLib для списка чатов и восстановления архива](issues/01-delivery-research.md): подтверждены способы получения чатов и истории; выявлены ограничения восстановления правок/удалений, идентичности исходящих сообщений и очереди обновлений.
- [Жизненный цикл наблюдения и границы полноты архива](issues/02-observation-lifecycle.md): согласованы периоды сбора, принадлежность аккаунту, восстановление с явными ограничениями и отсутствие воздействия на состояния сообщений в Telegram.
- [Модель архива и локальное хранилище секретаря](issues/03-archive-storage.md): согласованы SQLite в основном процессе без worker, граница `@daevox/db`, идентичность записей, периоды и прогресс, представление изменений и автоматические миграции.
- [Пользовательский сценарий выбора Telegram-чатов](issues/04-chat-settings-ui.md): принят вариант A на странице Telegram с отдельными переключателями, поиском/фильтрами, подробностями, настройкой без сети Telegram и сверкой состояния при конфликте или потере ответа.
- [Контракт настроек и алгоритм сбора сообщений](issues/05-ingestion-contract.md): согласованы HTTP/polling, версии настроек, постепенный каталог, порционная догрузка и слияние, временные границы, защита содержимого и явное возобновление при неопределённости.
- [Критерии приёмки и спецификация первого этапа секретаря](issues/06-acceptance-spec.md): определены проверки реализации, обязательный ручной прогон и нагрузочный ориентир; подготовлена [итоговая спецификация](spec.md).

- Скачивание вложений, распознавание изображений и расшифровка голосовых сообщений.
- Одновременное подключение нескольких Telegram-аккаунтов и многопользовательский сервис.
- Пользовательская очистка архива в первой версии: пользователь отклонил её включение при согласовании [Жизненного цикла наблюдения и границ полноты архива](issues/02-observation-lifecycle.md).
