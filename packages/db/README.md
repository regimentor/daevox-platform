# Архив SQLite / Drizzle

Схема описана в `src/schema.ts`, запросы и транзакции используют Drizzle ORM с драйвером
`node:sqlite`. Версии ORM и Kit закреплены на `1.0.0-rc.4`: эта версия поддерживает
встроенный SQLite-драйвер Node.js 26.

В корневом `.env` задаётся URL файла:

```dotenv
DATABASE_URL=file:///absolute/path/to/daevox-platform/db/daevox.sqlite
```

По умолчанию используется `db/daevox.sqlite` в корне репозитория. Переносимый вариант:
`DATABASE_URL=file:./db/daevox.sqlite`. Относительный путь всегда считается от корня репозитория,
а не текущего рабочего каталога. Пробелы в абсолютном URL кодируются как `%20`.
На границе драйвера URL преобразуется через `fileURLToPath`, поскольку `node:sqlite`
ожидает путь файла. Файл, WAL и SHM исключены из Git.

Перед первым запуском backend и после изменения схемы выполнить из корня:

```sh
npm run db:push
```

Или из workspace: `npm run db:push -w @daevox/db`. Команда запускает `drizzle-kit push`,
сравнивает описанную схему с файлом и применяет изменения. SQL-миграции не генерируются,
backend самостоятельно схему не изменяет. Не используйте `--force` для рабочего архива;
перед изменениями существующих таблиц сохраните SQLite backup.

Таблица `schema_migrations` сохранена для совместимости со старым архивом и больше не управляет
миграциями. Старую базу можно использовать, указав её file URL и выполнив `db:push`.

Проверки: `npm run verify -w @daevox/db`. Тесты создают временные базы через тот же Drizzle push
и не обращаются к рабочему архиву.
